# Offline acquisition tasks

Own configured schedule, campaign-role and approved-proposal task admission, immutable supplied proposal revisions and attributable human approvals, immutable scope/limits, execution ownership, attempts, durable completion identities/inbox, phase/outcome counts and links to ingestion runs and knowledge publications. Public interfaces are `AcquisitionTasks`, `CompletionInbox`, `EnrichmentProposal`, trusted `TaskAuthority`/`OfflineRoute`, `OfflineTaskWorker.run_one` and its `TaskExecution` handle; read [the task contract](../../docs/tasks.md) before changing authority, owner transactions or recovery.

Read campaigns through `CampaignStore` and pin current-brief admission with its `require_current_brief` on the admission connection; ingestion owns source persistence/normalization and exact support; `KnowledgePublications` owns availability and unchanged-support comparison. Keep dependencies toward these public owners and task-table writes within this package. Retain actual initiator/worker identities and exact brief, run, support and publication IDs. Store source-free metadata rather than raw payloads or copied source wording.

Construct actors at trusted CLI/HTTP boundaries. Resolve campaign/approval roles from operator-owned `TaskAuthority` at composition boundaries. Campaign admission requires its configured identity/kind role and an existing workspace campaign. Assistant admission reads an exact saved human approval; preserve one proposal/approval/task binding and original retry request identities. Keep authority configuration outside assistant/form control. Persist scope/configuration digest and hard limits before acknowledgment; queued execution verifies that digest. The task worker registers only the saved synthetic `fixture-json` supplied-reference or `offline-keyword-json` discovery capability and runs at most one task. Keep collection, ingestion, publication and usable-update meanings distinct. Terminal retries reopen existing effects. Recovery reuses the original attempt/run and exact prepared support, retaining total handoff count and bounded actor/phase history. Commit the task-owned publication receipt in the actual publication transaction. Before unchanged-support filtering, use `read_committed_publication` to validate that receipt, exact durable prepared support and source-owned attempt/run lineage; request text alone grants no task ownership. A lost acknowledgment retains the original publication, producer and historical outcome under current policy.

Persist evidence/canonical/publication frontiers and actual sanitized coverage through public owner operations. Publish valid subsets as partial updates with the failed remainder visible. Keep waiting provider checkpoints with ingestion; expose safe resume versus ambiguous reconciliation without blindly reissuing an operation. Trusted collector injection simulates fixture I/O only; observer exceptions interrupt execution without becoming task failures.

Derive worker task identity and actor from its `TaskExecution` handle. Normalize task UUIDs before forming ownership/publication identities. Claim one task-specific session lock, rechecking terminal state atomically. Route every dependent mutation through `TaskExecution.transaction` on that same ownership connection, including run checkpoints/issues/status, canonical effects, publication and completion. Keep I/O outside transactions. A token check followed by effects on another connection breaks fencing. Session loss raises `TaskExecutionLost`; retain successor effects and recover committed progress. See [ADR 0005](../../docs/adr/0005-task-session-effect-ownership.md) for connected-worker and external-operation limits. The completion event joins that fenced terminal transaction; `CompletionInbox` reopens source-free historical outcomes and current-policy publication navigation. `resolve_cost_attribution` reopens exact tasks and validates attempt membership for injected accounting consumers; keep this public seam free of accounting imports or writes. The worker reopens the immutable operator cost-route binding and composes `SyntheticOperationAdapter` at the actual collector dispatch. Admission/settlement use `TaskExecution.transaction` on this same session; scheduled, campaign and approved-assistant origins share the guard. Retain nonterminal waiting reasons/allowance on refusal and never reissue dispatched/settled retry identities after response loss. Final accounting reconciliation keeps dispatched identities settled; explicit meter recovery permits only future operations. Retain waiting when a response is unavailable and preserve session fencing/publication receipts independently. Forecast-only routes retain independent request/record/byte limits. Task migration installs the independent accounting and schedule schemas; accounting has no task import. Cost control restricts execution without broadening task authority. Verify real competing public workers/processes, session-loss commit boundaries and independent task progress; update contracts, architecture and the physical ERD together.

For discovery, read the bounded keyword section of the task contract. Require one explicit query, subjects and publication window from the exact approved proposal. Pin selection/configuration/hard limits and revalidate before dispatch; use source-owned selection coverage and stable namespace identities. Preserve legacy fixture serialization/hashes. Recovery validates exact prepared support/receipts before needing source files; malformed selection rows retain partial/failure semantics.

`submit_campaign_discovery` admits only a saved coverage decision and an operator-configured campaign role. Pin the exact current human brief through `require_current_brief`; derive one catalog-name query/subject and the saved-clock window under the [coverage contract](../../docs/campaigns.md#automatic-coverage-and-discovery). The one-per-shortlist `campaign_discovery_requests` row commits with its fresh server-owned nested task, or with a sanitized refusal/not-needed disposition. Reopen that disposition before reading changed policy, clock, brief or route; never adopt a client-preclaimed task identity. `read_campaign_discovery` joins current task progress without copying it. `CampaignRecommendations` in `campaigns/` owns save-first public application composition; ordinary supplied-reference campaign submission still cannot infer discovery from purpose prose.


For registered keyword configuration, due ticks or schedule authority, follow [the schedule owner's instructions](schedules/AGENTS.md). `ScheduledDiscovery` owns all schedule SQL and composes task admission on the same transaction. `submit_scheduled` requires a configured tick role and reopens actual schedule-owned occurrence authority; accept only the occurrence identity, never client query/origin/accounting fields. Preserve `schedule_occurrence_id` and the exact immutable configuration/keyword/day context in task scope. A schedule is not a proposal approval and grants no live-route capability. The existing worker executes these offline query tasks with the same session/cost/receipt boundaries.

Scheduled workers compose `ScheduledPostAllowance.admit` through the ingestion owner’s `CanonicalAdmission` seam on the same `TaskExecution.transaction`. The schedule owner alone issues allowance SQL; immutable scope is unchanged when current day cap/usage evolves. Task `daily_allowance` reopens that day’s current enforcement and occurrence counts independently of persisted execution coverage. Keep new-post debits separate from refreshes, publication availability and request/record/cost limits.
