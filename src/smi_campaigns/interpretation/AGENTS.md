# Bounded generated campaign criteria

Own the criteria-specific OpenAI Responses request/response mapping and validated generated criteria. The shared `responses` module owns the concrete disabled-by-default HTTPS adapter, route bounds, token-weight policy and monetary dispatch. `ResponsesRoute` is trusted server configuration; `ResponsesTransport.create` is the service port and `ResponsesHTTPTransport.connection_factory` the external HTTP test seam. `CampaignStore.interpret_criteria` owns SQL, attempt identity and revision fencing. Read [the campaign contract](../../../docs/campaigns.md#bounded-natural-language-interpretation) before changing this flow.

Provider dispatch requires explicit server enablement, credential, the verified snapshot contract/input cap, standard service tier, positive configured rates and finite request/output/response/time bounds. Use no tools, storage, retries or paid preflight. Match route/transport/cost measurement basis; preserve synthetic fixture compatibility without permitting real HTTP under synthetic classification. Validate final model/status/tier before usage settlement; unknown/partial consumption retains liability. Capture all generated usage and cache details through the cost owner's public ports, without labelling provider reports synthetic or claiming invoice verification. Keep credentials, prompts, raw responses and exception strings out of persistence.

Use public `responses.generated_document` for envelope, refusal and JSON validation. Preserve criteria-specific `refused/model_refusal` and sanitized invalid-output outcomes; criteria field validation remains here.

Generated criteria append namespaced additions to unchanged human constraints. Independently validate every supported field/policy and preserve exact original brief plus model/method/schema provenance. Model strings confer no acquisition, approval or verified-fact authority. Display success before explicit later profile selection; retain failed/stale/uncertain attempts without mutating human briefs or automatically assessing. Public-operation/HTTP tests use real PostgreSQL and intercepted simulated external connections; model/source execution remains simulated in default verification.
