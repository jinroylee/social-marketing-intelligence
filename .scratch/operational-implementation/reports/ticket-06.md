# Ticket 06: recover interrupted tasks and expose partial outcomes

Status: implemented locally; ticket remains claimed for integration verification.

## Installed behavior and public interfaces

- `OfflineTaskWorker.run_one(task_id, automation_actor)` executes or resumes the same logical attempt/run. It reuses committed observations/checkpoints and canonical support, retaining original admitted scope, exact campaign or approved-proposal authority and hard limits. Recovery records its actual actor in `attempts[].resumed_by`; it creates no new attempt. Terminal retries return the original result.
- Trusted `OfflineTaskWorker(..., on_progress=callback)` observes source-free snapshots after evidence/canonical commits, publication preparation/commit, waiting and completion. Callback exceptions propagate as process interruptions. Tests inject faults through this public operation rather than replacing private methods or querying task tables.
- `IngestionRunner.resume(run_id, on_commit=callback)` reports `evidence_committed` / `canonical_committed` plus observation identity after their owner commits. `inspect(run_id)` reads actual counts/issues without collecting, finishing or otherwise advancing a run. Evidence and collection checkpoints remain source-owned; canonical application remains with its existing writer.
- `acquisition_tasks.progress` stores the phase/observation frontier; attempts store exact `publication_support` observation/derivation/assertion/metric IDs before publication. Recovery after that preparation reuses the selection without refetching or reselecting. Publication still checks current process permission and derivation health at commit.
- `KnowledgePublications.find_request(request_id, actor, include_synthetic=...)` reopens source-free committed publication metadata with original producer and coverage. Task reads and recovery use `task:TASK_ID` before unchanged-support comparison, covering the publication-commit/task-acknowledgment gap. An interrupted committed update remains visible with actual published count/link; recovery retains usable/partial outcome, publication identity and original publication producer even under a different worker actor and after input files are removed.
- Outcomes now include `partial_update`: valid newly usable support commits even when another record fails mapping/collection or a bound leaves incomplete input. The failed phase/code and remainder stay visible. With no new committed subset, execution errors remain `failure`; empty eligible or unchanged currently usable input remains `no_usable_update`. No new publication or market-absence claim is invented. Unpublished support stays unavailable to current-KB queries.
- Coverage distinguishes requested, collected, applied, quarantined, remaining, ineligible, eligible, unchanged, unpublished and published material, plus actual reported request/byte use, unresolved identities, missing fields and sanitized issue codes. Publication withdrawal reports the publication phase and its unpublished member count without a usable-update claim. The local task detail displays exact progress, wait reason and resumability.
- Trusted `collector=...` supplies simulated fixture I/O through the existing `Collector` interface; only the `fixture-json` mapper/route is registered. `CollectedBatch` adds optional no-observation waiting and actual request-attempt fields. `EvidenceStore.advance` atomically saves the opaque checkpoint, completion/waiting metadata and usage, bounded by persisted limits. `ingestion_runs.waiting` exposes only a reason/resumability pair to the task owner.
- `provider_pending` requires an adapter guarantee that replaying its checkpoint safely resumes the existing operation. `provider_operation_ambiguous` remains waiting with `resumable=false`; another worker invocation makes no collector call. Pending work exhausts its persisted request bound before another call. This is simulated local contract coverage, not a live provider rollout or a monetary guarantee.
- Migration preserves existing task/approval/attempt/run identities and adds only progress, recovery actors, prepared support and ingestion wait metadata, plus the waiting task status. Existing exact human-approval authority and source/publication ownership are unchanged. Contracts, architecture, physical ERD, dictionary and local browser/operator docs are aligned. Ingestion now has concise owner instructions with a relative `CLAUDE.md -> AGENTS.md`; existing task/publication instructions describe their new invariants.

## Extension notes for ticket 07 and limits

- This is single-worker recovery. `run_one` is deliberately not a claim/lease/fencing protocol; ticket 07 must coordinate ownership and stale-worker handoff around the existing task/attempt/run frontier. Recheck terminal state and ownership in that claim transaction before effects. Recovery must retain prepared support, task request identity, original publication producer and committed coverage.
- The public progress callback and injected collector are cohesive test/composition ports. Keep fault-injection tests there; preserve real persistence and current policy. Prepared support and request-bound publication lookup are the durable handoff points, not an instruction to retry whole acquisition.
- Pending checkpoint replay is safe only under its adapter promise. Ambiguous-operation reconciliation remains a route-specific external requirement; this ticket exposes the condition and prevents blind reissue. It enables no real provider, paid operation, live model, general queue, notification, meter or monetary admission.
- Retained pending evidence can replay without source I/O. If an interruption loses an intentionally non-retained transient payload, recovery reports unavailable replay rather than refetching. Current input configuration is required until publication preparation; a prepared/committed publication can finish without input files.
- Original task outcomes remain historical, while publication/query readers continue applying current source policy. Technical test success does not establish language quality, marketer usefulness, market completeness or live-route readiness.
