# Local review application

Own localhost HTTP handling, form parsing and escaped HTML evidence panels. `ReviewApp` composes public monitoring, campaign/planning, knowledge and frozen-evidence interfaces; `make_server` binds the application to loopback. Database writes and decision rules remain in their domain stores.

Construct the named human and preparation-worker actors on the server. Forms carry request IDs and expected versions; preserve submitted edits on recoverable errors, and require an explicit human confirmation. Recheck display policy through public readers when rendering. Render captions only for available/current candidate support, and keep provisional interpretations, human reasons and unknowns visibly distinct.

Brief forms preserve original human prose and stable criterion IDs on edits/errors. Render the campaign owner's saved profile beside the original input and exact historical brief; use its installed version labels and explicit legacy-unrecorded state. Profile/method versions are server-owned metadata, not form authority.

Allow only the server's loopback Host and same-origin writes with its CSRF token. Escape all data; source URLs are validated external links, never fetched or embedded. Serve only fixed bundled assets. Keep browser state out of durable decisions: PostgreSQL revisions own save/reopen behavior.

Keep investigations, knowledge search and publication list/detail pages independently reachable from campaigns. Search forms use `KnowledgeQueries` to preserve actual result membership; result pages reopen current display policy and show explicit scan/result limits and freshness. Publication pages read committed membership through `KnowledgePublications`, showing denied/superseded support metadata without source text. Proposed measurement and human feedback stay distinct from observed outcomes. Feedback error pages withhold submitted source-dependent text when support is unavailable.

Save supplied immutable proposals and approve their displayed scope only through the configured human action. Preserve escaped proposal/task edits and retry identities on recoverable errors. Reopen protected brief/digest scope from the domain owner, preserving recognized historical campaign basis and the durable approval request identity rather than trusting forged authority fields. Reopen approval-only interrupted actions with their durable request identity; render exact task/proposal links and keep conversation generation outside this surface. Submit configured offline campaign tasks through `AcquisitionTasks` and render source-free task/run/publication lineage independently through task list/detail routes. The server chooses the synthetic fixture route, actor and origin; form fields cannot grant origin, approval or live-collector authority. Acknowledgment does not execute the worker.

Render `/costs` and task cost/detail routes through `UsageAccounting`, showing synthetic measurements separately from forecasts, declared commitments and unknown/failure coverage. Compose the task owner's public attribution resolver at this boundary; forms cannot configure rates, ceilings or route bindings, or assert usage. Render actual scope allowance and operation admission status; show enforced synthetic control only for configured metered scopes and preserve forecast/unknown coverage. Reopen current cost bounds, billing state and meter health on relevant task detail independently of saved progress. Keep final reconciliation, active unresolved identities and recovery evidence visible on cost detail, with explicit delayed/unbounded-charge enforcement limits. Reconciliation and recovery remain trusted Python operations; forms confer neither authority.

Render `/inbox` and completion detail through `CompletionInbox`, including only its currently permitted publication links. Keep historical published counts separate from current availability and retain the task link when support becomes unavailable.

Task detail reads execution ownership from `AcquisitionTasks`: distinguish active running work from recoverable committed progress and waiting/terminal states. Keep worker disconnect/transaction observers at trusted composition boundaries; forms cannot revoke claims or choose execution IDs.

Update `docs/local-review.md` when changing routes or operator behavior. Verify server-bound actor identity, stale saves, policy withdrawal, error-state preservation and restart/reopen using isolated schemas. The application does not acquire live evidence, run paid models or translate captions.

Compose optional explicitly classified model configuration through the trusted constructor. Campaign interpretation forms carry only request/brief/version and CSRF context; reject authority/configuration fields and preserve stale retry context on errors. Display generated criteria and their exact model/method/schema/input basis before offering explicit selection in the comparison form. Reopen saved outcomes independently of configured transport after restart. Render cost links and provider/simulated/unavailable/uncertain states truthfully; provider HTTP requires trusted explicit server enablement; forms and environment keys confer none.
