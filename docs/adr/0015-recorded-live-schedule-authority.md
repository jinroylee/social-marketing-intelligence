# Record live schedule authority separately from process enablement

Status: accepted

A manifest switch or process enablement must not silently convert an existing offline keyword schedule into paid recurring authority. Require an explicit configured human operator save, and pin its exact live route/version/manifest/limits/policy in an immutable schedule configuration and each acknowledged occurrence. Later saves affect future occurrences; existing tasks retain their original authority. Runtime credentials, source-use/operation authorization, current policy and spending admission remain independent gates. This trades automatic configuration adoption for auditable bounded authority without a new scheduling engine.

Stop new live POST work when the occurrence day's shared new-post allowance is exhausted. Successful post consumption still commits only with canonical effects, so already-started competing requests may return and be excluded rather than reserving capacity for an unknown response. Allow progress/download GET recovery of an already dispatched snapshot after post-cap exhaustion, subject to every existing monetary, request/byte, runtime and not-before gate. Discarding a known handle would lose the response without removing its unknown billing liability; recovery never creates another POST or silently releases that commitment.
