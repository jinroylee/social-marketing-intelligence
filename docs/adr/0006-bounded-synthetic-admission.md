# Reserve one bounded synthetic dispatch under the scope lock

Status: accepted

The offline accounting owner already retains immutable scope/rate/currency/period configuration, measured synthetic amounts, append-only declared commitments and explicit unknown coverage. A bounded simulated operation must receive one authoritative allowance before dispatch, including when tasks or independent operation adapters compete on separate connections/processes. A successful retry must not grant another invocation against an existing reservation.

Serialize each decision and every relevant ledger write on the configured scope row. The available ceiling subtracts all measured usage, all legacy declared commitments and every dispatched bounded reservation across the full scope. Explicit unknown/meter-failure coverage blocks further metered dispatch. Commit a single operation-bound reservation before simulated I/O; successful bounded settlement atomically appends one usage measurement and marks that reservation settled. A settled or already dispatched operation never invokes its transport again. Independent actual reporting remains truthful and serialized, even if it reveals spend beyond the ceiling.

Task composition reopens a persistent operator route binding and injects the public attribution resolver. The admission/settlement transactions join the same task ownership session used for task/source/publication effects. Accounting retains no task dependency or foreign-table reads. Both campaign and exact approved-assistant tasks use this collector boundary, preserving authority and resource limits. Forecast-only bindings retain request/record/byte bounds independently.

Holding a database transaction across transport I/O would prolong locks and still leave ambiguous remote outcomes after process loss. A check followed by an unfenced reservation on another task session would allow stale effects. Automatically releasing a reservation on timeout or retry would authorize another possible charge. Instead, a failed/lost response conservatively retains its commitment and pauses that operation; even a settled result lost before ingestion cannot be blindly fetched again. No declaration-release operation exists, so legacy declarations remain liabilities after usage arrives. A future explicit reconciliation contract can resolve supported cases.

This decision enforces allowance for the trusted bounded fake service contract only. It does not enable commercial providers, establish provider-side exactly-once billing, or promise zero overshoot for delayed/unbounded charges. Pure unbound local fixture reads remain their existing workflow; configuring the route establishes the shared controlled simulation for every later worker invocation. Costs and task progress expose exact refusal/paused reasons and synthetic monetary control separately from human approval and current source permission.
