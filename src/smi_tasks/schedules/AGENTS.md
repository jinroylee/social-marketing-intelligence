# Registered keyword schedule

Own versioned workspace keyword configuration and daily occurrence history, including accounting-day context and immutable admission/refusal dispositions. `ScheduledDiscovery.configure`, `read`, `read_occurrence` and `tick` are the public application operations. Read [the schedule contract](../../../docs/tasks.md#registered-offline-keyword-schedule) before changing cadence, authority or history; [ADR 0011](../../../docs/adr/0011-stable-schedule-accounting-day.md) explains fixed accounting identity.

Inject `AcquisitionTasks` at composition. Only this directory reads/writes schedule tables. `require_occurrence` reopens exact recorded authority on the caller-owned admission connection; the task owner uses it rather than accepting supplied keyword/context fields. Keep runtime imports acyclic through injection/type-only task references. The task owner writes task tables; ingestion, publication, notifications and cost controls retain their existing public owners.

Serialize configuration and due ticks on the same workspace lock. Commit each bounded tick's occurrence dispositions and nested task admissions together, without source/model I/O. A pending occurrence exists only inside that transaction. Preserve stable keyword keys and workspace/local-day uniqueness across configuration revisions, removal, re-registration and process restart. The first accounting timezone remains fixed; versions and allowance edits never identify a new accounting day. Capture trusted clock time after taking the serialization lock and reject regressions. Read settings/version history from a consistent snapshot.

Keep the route explicitly offline. Tick authority comes from exact operator-configured human/service roles; actor kind, forms and assistant text confer none. Tick acknowledges at most ten current-day tasks and never executes collection or catches up missed days. Refused occurrences remain refused for that day. Worker execution retains immutable selection/configuration digests, hard limits, source policy, cost admission, session fencing and exact publication receipts. The allowance is installed through `ScheduledPostAllowance` in `allowance.py`. It owns day metadata and per-observation admission SQL. `admit` joins canonical application on the caller’s fenced connection after current policy/normalization and canonical identity locks; successful new admission and canonical writes commit together. Known refreshes/deduplicated identities consume no extra new-post debit. Skipped records retain evidence but no canonical effects. Configure the current day’s cap/version without resetting history; decrease below usage yields remaining zero. Bootstrap upgraded days under the schedule lock from the latest configuration recorded before fixed day end, and keep cap versions monotonic. Preserve historical task authority markers separately from current enforcement reads. Read the [atomic admission ADR](../../../docs/adr/0012-atomic-scheduled-post-admission.md) before changing novelty, rollback or cap-edit semantics.

Test through public schedule/task/current-KB readers and HTTP with real PostgreSQL and simulated source I/O. Fault-only DDL is permitted; verify rollback through public readers. Avoid private-method tests, schedule SQL outside this owner, task SQL here, client-selected origin, resetting history on edits, I/O in transactions, automatic worker/daemon activation or live providers.
