# Preserve schedule accounting days across configuration edits

Status: accepted

A registered keyword may change query, be removed and later return, while its prior due tasks and resource consumption still belong to their original day. Configuration version is acquisition authority, not a fresh accounting identity. Using version or keyword text as the day key would let routine edits silently reset history and would obstruct shared new-post admission.

The local offline schedule fixes its IANA accounting timezone on the first configuration. Its day begins at local midnight, with exact UTC start/end saved on every occurrence and task. One stable keyword key has at most one occurrence per workspace/local date, independently of configuration version. Query, daily time, lookback and allowance changes create immutable successor configurations; removal and re-registration preserve earlier occurrences. A new key denotes a distinct registration, and never a new accounting day. The daily consumption ledger must join workspace/day across all configuration and keyword versions, including edits to the recorded allowance.

The installed cadence acknowledges only the current local day's due work. Missed earlier dates are not replayed; explicit refusal remains the disposition for that keyword/day even if route configuration later improves. Daily-time overlaps use the earlier instant, and nonexistent times move forward by the offset gap. Stable day boundaries retain the actual 23/24/25-hour timezone interval. Worker execution uses its recorded immutable task scope and the existing fenced effects, independently of later schedule edits.

Allowing timezone edits would require a migration policy for overlapping or truncated accounting windows and previously admitted consumption. Resetting at each configuration or replaying missed days would create new load and weaken predictable bounded operation. This initial route instead chooses fixed accounting identity and current-day-only admission; timezone migration, automatic backfill and external cron/daemon deployment are outside it. The configurable allowance initially records a target of 50 unique eligible new posts total across at most ten registered keywords. Atomic new-post enforcement now joins canonical effects as described in [ADR 0012](0012-atomic-scheduled-post-admission.md); schedule configuration alone never implies successful throughput. This accounting identity applies to default offline work and [explicitly activated live schedules](0015-recorded-live-schedule-authority.md).
