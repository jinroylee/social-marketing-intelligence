# Design plan, revision r1

Question: can a marketer move from a beauty campaign brief to an evidence-backed saved shortlist, then explore and improve knowledge without confusing a suggestion with authority?

Three structural variants share one fixture application through `?variant=A`, `B`, or `C`. This is a new scratch prototype because the installed server uses owner-bound Python forms; mounting into it would imply production adapter work outside this task.

- A, Evidence workspace, is recommended. A vertical destination rail keeps campaign work anchored; a contextual right inspector keeps evidence beside the decision.
- B, Campaign desk, uses horizontal destination navigation and a full-width decision area. Evidence follows below. This favors comparison at the expense of simultaneous support.
- C, Research notebook, places the current question before navigation and uses a narrow reading column. Evidence precedes the main work. This favors source review but slows shortlist scanning.

Tokens use Signal red #E6002A for primary actions, Petal #F4ABAF for selected regions, Graphite #3E3A39 for text and graph canvas, and White #FFFFFF for the workspace. Borders use graphite with transparency. White/red and graphite/white carry text; petal never carries white text. System font stacks favor Apple SD Gothic Neo, Hiragino Sans, and Noto Sans CJK with no network font request. Body 15/1.55, labels 13, title 30, page heading 38. Text wraps naturally, including Japanese captions, without uppercasing or letter spacing.

The memorable element is the relationship canvas. Node shapes distinguish account, post and catalog entities; line patterns distinguish observed, derived and human associations. Inspector wording explains what a connection can support. The rest uses quiet dividers and a small number of purposeful panels, avoiding a dashboard of identical metric cards.

Brief review found a generic card-grid home would hide the actual decision. The plan therefore starts inside a populated campaign, with current brief, visible criteria and a saved recommendation. Implementation/readiness mapping belongs in the specification, while fixture labeling stays global and unavailable states appear beside affected actions.

All interactions are in-memory fixture transitions. No external requests, storage, production mutation, contact or email delivery occur. Human approval of the design remains pending; no prototype choice is an accepted product contract.
