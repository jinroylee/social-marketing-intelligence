# Attributable offline cost accounting

The installed `smi_costs` owner records synthetic measured usage, derived synthetic amounts, forecasts, declared outstanding commitments and explicit uncertainty. Its public `UsageAccounting` operations use real PostgreSQL and trusted workspace/actor contexts. No provider/model call, commercial charge, spending admission, ceiling or worker meter is enabled by these operations. [Hybrid spending control](functional-requirements.md#hybrid-spending-control) remains the target for later admission/reconciliation.

## Configuration and attribution

`UsageAccounting(db, workspace_id='local', task_attribution=resolver)` owns three tables and has an independent idempotent `migrate()`. `smi-ingest migrate` installs it. `configure_scope(CostScope(...), human_actor)` requires a workspace human operator and persists an immutable workspace/scope identity. Configuration includes provider, service, `metered` or `forecast_only` classification, uppercase three-letter currency code and an explicit timezone-aware accounting interval. The interval is start-inclusive and end-exclusive, normalized to UTC. Currency codes are operator declarations; this module performs no exchange conversion or currency registry lookup.

A metered scope additionally requires unit, rate version and exact nonnegative unit rate. This milestone supports only **synthetic** metered configuration: the public scope document explicitly marks that basis. Rates are supplied by the operator for simulation, not retrieved commercial prices. Forecast-only scopes accept no meter/rate fields. Missing configuration fails; meter failure cannot reclassify the scope. Changed rate, period, currency or classification under an existing identity raises `cost_scope_conflict`; use a new scope identity for new configuration. The original operator and configuration time remain readable.

`begin_operation(scope_id, actor, request_id=..., method=..., task_id=None, attempt_id=None)` commits an operation before a meter result. Workspace/request identity pins scope, actual actor/kind, method version and optional exact task/attempt. Identical concurrent retries retain one UUID; changed reuse raises `cost_operation_conflict`. Method and service identify equivalent operations, including synthetic model operations with no acquisition task. No-task attribution still requires an actor, method and stable request identity.

Task and attempt must be supplied together. Task-linked operation creation requires an injected public resolver with `(task_id, attempt_id, actor) -> {'task_id': ..., 'attempt_id': ...}`. `AcquisitionTasks.resolve_cost_attribution` normalizes IDs, reopens the task through its public workspace boundary and verifies exact attempt membership. Foreign/nonexistent tasks or foreign/unrelated/nonexistent attempts are rejected. Accounting neither queries task tables nor imports the task package; tasks do not depend on accounting. The local application composes these owners. Persisted task references are public-owner-validated logical references, without a cross-owner SQL foreign key. Historical accounting reads remain independent of source payload permission, publication availability and task route configuration.

## Measurements and nonactual records

`record_usage(operation_id, actor, measurement_id=..., units=..., rate_version=..., measured_at=..., provenance=...)` derives `units × configured unit_rate` exactly. It rejects forecast-only scopes, wrong rate versions and measurements outside the accounting interval. Entries retain units/unit, exact rate and version, derived amount, timezone-aware measurement time, source-free measurement provenance, actual recorder and database recording time. These are synthetic measurements, explicitly **not commercial charges**.

Numeric inputs accept decimal strings, `Decimal` or integers, with values from zero through `10^18`, at most 12 fractional places and exponent from −12 through 18. Floats, booleans, negatives, invalid/nonfinite values and unsupported precision fail before recording. Products/totals use a separate 80-digit decimal context and canonical decimal strings; no binary float or rounding to currency minor units is introduced. An explicit measured zero is distinct from missing measurements.

The following operations keep distinct entry kinds:

| Public operation | Meaning |
| --- | --- |
| `record_forecast(..., amount, currency, measured_at, provenance, assumptions)` | Additive estimate for this operation with explicit assumptions, available for either classification |
| `record_commitment(..., amount, currency, measured_at, provenance)` | Declared outstanding synthetic amount for a metered operation; observational only, with no reservation/admission |
| `record_uncertainty(..., state='unknown' or 'meter_failure', measured_at, provenance, reason)` | Durable unknown coverage or expected-meter failure; no invented monetary amount |

All records require a stable `measurement_id`, unique across the workspace, not just within an operation. Identical content/recorder/kind/operation retries reconcile once, including concurrent calls and after restart. Changed reuse raises visible `cost_measurement_conflict` and preserves the original record. Normalized operation UUID spellings retain the same identity. No entry is silently overwritten. Forecast and commitment identities represent independent additive portions, not replacement estimate revisions. They never become actuals because a usage record arrives. Declared commitments remain outstanding indefinitely in this milestone: there is no release/resolution API, and usage arrival does not reduce their amount.

## Reads and local detail

`read(operation_id, actor)` returns immutable configuration/attribution, exact entries and separate `actuals`, `forecasts` and `commitments` totals. An absent category has `amount: null`, rendered **Unknown**, rather than zero. Actuals explicitly report `synthetic: true`, `commercial_charge: false`; `enforced_monetary_control` is always false. Totals combine only entries of the same operation, configured currency and period. No cross-currency or period total is invented.

Coverage states distinguish `unmeasured`, `synthetic_measured`, `forecast_only`, `unknown` and `meter_failure`. `unknown_cost` remains true for forecast-only/missing measurements and any explicit uncertainty. A measured amount is the known portion; an explicit unknown or failure remains visible after late measurements. This milestone retains those uncertainty records without resolving them or declaring complete commercial coverage. Configuration classification stays fixed.

`list(actor, task_id=None)` returns the newest 100 workspace operations; older operation identities remain directly readable. A task filter selects accounting metadata without asserting task existence; callers needing an existing task reopen it through `AcquisitionTasks` first. Every read/write checks workspace. Accounting stores source-free operational metadata, never source payload, captions, URLs, prompts, responses, credentials or unrestricted explanations. Callers supply sanitized provenance/reason/method identifiers. Revoking source support therefore does not erase measured historical resource usage or expose denied source values.

**Costs**, `GET /costs`, `GET /costs/OPERATION_ID` and task detail's `GET /tasks/TASK_ID/costs` use these public interfaces. The task route reopens the owning task first. Pages escape metadata, show exact attribution/provenance, separate amounts, synthetic basis and the absence of enforced monetary control. Missing records establish unknown coverage. Configuration and recording remain trusted Python operations; no browser form can configure a rate, assert a measurement or grant spending authority.

## Extension boundary

Accounting does not automatically meter existing fixture workers or source/model tools. It does not release/reconcile declared commitments, clear uncertain calls, create ceilings or reserve allowances. Later admission must include every existing outstanding declaration in its authoritative scope accounting, or expose admission as unavailable until those liabilities can be resolved. The bounded newest-100 operation list is a presentation interface and cannot establish full-scope allowance. Later admission must compose the public task/worker effect and dispatch protocol with shared accounting, keeping dependencies acyclic and preserving exact operations/measurement identities. A pending synthetic declaration is not proof that a remote call was safely bounded or free. Live chargeable work requires a separately validated meter/admission/reconciliation contract; this offline accounting path grants no such authority.
