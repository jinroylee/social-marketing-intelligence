# TikTok sandbox and Bright Data source mechanics

**Checked:** 2026-09-30. Primary-source documentation review only. No local credentials were opened or used; no account, TikTok page, or provider collection was accessed. This note addresses **technical access and integration shape**, separately from any source or downstream use rights.

## What the regular TikTok sandbox credentials can do

- A TikTok developer app sandbox lets a developer test product configuration before app review. Its **target users must be TikTok accounts the developer owns and adds by logging in**, up to ten accounts; Login Kit authorization is a further step. A client key/secret for that sandbox is therefore a useful way to test an OAuth integration with those target users, not a grant to fetch arbitrary public creator histories. [TikTok Add a Sandbox](https://developers.tiktok.com/docs/en/add-a-sandbox).
- The Display API's `/v2/user/info/`, `/v2/video/list/`, and `/v2/video/query/` require the relevant `user.info.basic`/`video.list` scopes and a **creator-authorized user access token**. TikTok says app scope approval alone does not give access to a user's data; each user must authorize, and `/v2/video/list/` is the public videos of the *token-bearing user*. This could support first-party or participating-creator evidence later, but cannot refresh `@maronayannyan` or other nonparticipating creators simply by supplying their handle. [Display API overview](https://developers.tiktok.com/docs/en/display-api-overview), [Display API get started](https://developers.tiktok.com/docs/en/display-api-get-started), [scopes](https://developers.tiktok.com/docs/en/scopes-overview), [List Videos](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-list).
- The Research Tools **do** describe public account/video data, but a normal developer account is insufficient: TikTok requires a separate approved research project and says creators, advertisers, and commercial users are ineligible. The Commercial Content API requires its own application and presently contains EU commercial-content data; its geographic dataset does not supply a Japan ordinary-creator feed. These are product-access limitations, distinct from any legal judgment about collecting public pages. [Research Tools](https://developers.tiktok.com/products/research-api), [Research FAQ](https://developers.tiktok.com/docs/en/research-api-faq), [Commercial Content API](https://developers.tiktok.com/products/commercial-content-api), [supported countries](https://developers.tiktok.com/docs/en/commercial-content-api-supported-countries).

## Bright Data technical route to test

- Bright Data publishes separate TikTok **profile-by-URL** and **posts-by-profile Fast API** datasets. The documented IDs are `gd_l1villgoiiidt09ci` for profiles and `gd_m7n5v2gq296pex2f5m` for posts by profile. The latter accepts `num_of_posts`, so a single supplied profile URL plus `num_of_posts: 10` is the appropriate technical probe for this pilot's ten-recent-post threshold. Its examples show post ID, description, creation time, share/comment/play counts and profile reference. The profile examples show follower, following, likes, video count, biography and profile URL. **These are vendor documentation examples, not a verified response for Japanese creators.** [TikTok scraper overview](https://docs.brightdata.com/products/scrapers/tiktok/introduction), [profile endpoint](https://docs.brightdata.com/api-reference/scrapers/social-media-apis/tiktok-profiles-collect-by-url), [posts-by-profile endpoint](https://docs.brightdata.com/api-reference/scrapers/social-media-apis/tiktok-posts-by-profile-fast-api-collect-by-url), [request examples](https://docs.brightdata.com/products/scrapers/tiktok/send-first-request).
- Setup requires a **separate Bright Data account/API key**; the TikTok sandbox key is not a Bright Data credential. Requests send `Authorization: Bearer <Bright Data API key>`. For a few profiles, `POST /datasets/v3/scrape?dataset_id=...&format=json` can return records directly; it accepts up to 20 URLs and waits up to one minute, then can return HTTP 202 plus a snapshot ID. For repeatable unattended runs, `POST /datasets/v3/trigger` returns a snapshot ID; poll `/datasets/v3/progress/{snapshot_id}` until `ready` (or handle `failed`/`canceled`), then fetch `/datasets/v3/snapshot/{snapshot_id}?format=json`. The provider recommends async/webhook integration because TikTok collector changes can affect latency. [TikTok request examples](https://docs.brightdata.com/products/scrapers/tiktok/send-first-request), [async workflow](https://docs.brightdata.com/products/scrapers/scrapers-library/async-requests), [TikTok overview](https://docs.brightdata.com/products/scrapers/tiktok/introduction).
- Bright Data advertises 5,000 free monthly records and pay-as-you-go at USD 1.50 per 1,000 records, but billing must be checked from an actual account/run. Its API FAQ says **invalid-input failures can still be billed**, despite product-page shorthand about successful-record pricing. It also notes that one input can return several output records and that TikTok media URLs may require a token from the same session; keep source post URLs and extracted fields rather than treating media URLs as durable. [Scraper API FAQ](https://docs.brightdata.com/products/scrapers/scrapers-library/faqs), [TikTok product pricing](https://brightdata.com/products/web-scraper/tiktok).
- Schema mapping needs a real sample. The Bright Data profile examples differ on whether `account_id` looks like a handle or a numeric ID; the posts-by-profile examples vary in which metric fields appear. Treat identity, ownership, `create_time`, `post_id`, `play_count`, `digg_count`, and possible partial/error rows as **unvalidated** until the exact selected endpoint is tested on the supplied creator and its outputs reconciled with the supplied TikTok video URL. A proxy `country` setting or returned region field is not evidence of Japanese audience demographics. [TikTok overview](https://docs.brightdata.com/products/scrapers/tiktok/introduction), [profile endpoint](https://docs.brightdata.com/api-reference/scrapers/social-media-apis/tiktok-profiles-collect-by-url), [posts-by-profile endpoint](https://docs.brightdata.com/api-reference/scrapers/social-media-apis/tiktok-posts-by-profile-fast-api-collect-by-url), [request examples](https://docs.brightdata.com/products/scrapers/tiktok/send-first-request).

**Implication for the source ticket:** the sandbox and Bright Data are complementary adapters, not alternative credentials for the same API. The sandbox can validate an authorized-creator OAuth path. Bright Data is the documented candidate for the requested arbitrary-public-creator refresh, but no live Japan response, ten-post completeness, current cost, or production reliability is established by these docs. Technical capability also does not by itself settle contractual use rights. No direct TikTok scraper or bot-detection bypass method was evaluated in this documentation review.
