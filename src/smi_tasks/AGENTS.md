# Offline acquisition tasks

Own campaign-role and approved-proposal task admission, immutable supplied proposal revisions and attributable human approvals, immutable scope/limits, execution ownership, attempts, phase/outcome counts and links to ingestion runs and knowledge publications. Public interfaces are `AcquisitionTasks`, `EnrichmentProposal`, trusted `TaskAuthority`/`OfflineRoute`, `OfflineTaskWorker.run_one` and its `TaskExecution` handle; read [the task contract](../../docs/tasks.md) before changing authority, owner transactions or recovery.

Read campaigns through `CampaignStore`; ingestion owns source persistence/normalization and exact support; `KnowledgePublications` owns availability and unchanged-support comparison. Keep dependencies toward these public owners and task-table writes within this package. Retain actual initiator/worker identities and exact brief, run, support and publication IDs. Store source-free metadata rather than raw payloads or copied source wording.

Construct actors at trusted CLI/HTTP boundaries. Resolve campaign/approval roles from operator-owned `TaskAuthority` at composition boundaries. Campaign admission requires its configured identity/kind role and an existing workspace campaign. Assistant admission reads an exact saved human approval; preserve one proposal/approval/task binding and original retry request identities. Keep authority configuration outside assistant/form control. Persist scope/configuration digest and hard limits before acknowledgment; queued execution verifies that digest. The task worker registers only synthetic local `fixture-json` capability and runs at most one task. Keep collection, ingestion, publication and usable-update meanings distinct. Terminal retries reopen existing effects. Recovery reuses the original attempt/run and exact prepared support, retaining total handoff count and bounded actor/phase history. Read request-bound committed publication metadata before unchanged-support filtering; a lost task acknowledgment cannot replace the original publication, producer or outcome.

Persist evidence/canonical/publication frontiers and actual sanitized coverage through public owner operations. Publish valid subsets as partial updates with the failed remainder visible. Keep waiting provider checkpoints with ingestion; expose safe resume versus ambiguous reconciliation without blindly reissuing an operation. Trusted collector injection simulates fixture I/O only; observer exceptions interrupt execution without becoming task failures.

Normalize task UUIDs before forming ownership/publication identities. Claim one task-specific session lock, rechecking terminal state atomically. Route every dependent mutation through `TaskExecution.transaction` on that same ownership connection, including run checkpoints/issues/status, canonical effects, publication and completion. Keep I/O outside transactions. A token check followed by effects on another connection breaks fencing. Session loss raises `TaskExecutionLost`; retain successor effects and recover committed progress. See [ADR 0005](../../docs/adr/0005-task-session-effect-ownership.md) for connected-worker and external-operation limits. Notifications and cost admission extend this owner without broadening task authority. Verify real competing public workers/processes, session-loss commit boundaries and independent task progress; update contracts, architecture and the physical ERD together.
