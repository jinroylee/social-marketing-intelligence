# Ticket 04: run one authorized offline acquisition task

Status: implemented locally; ticket remains claimed for integration validation.

## Behavior and public interfaces

- New `smi_tasks.AcquisitionTasks(db, workspace_id="local", route=OfflineRoute|None)` owns durable campaign task admission and source-free read/list metadata. `submit_campaign(campaign_id, actor, brief_id=..., purpose=..., request_id=...)` reopens a real workspace campaign and pins its exact current brief. The server establishes campaign origin; no submitted origin, actor kind, model statement or approval flag grants authority. Foreign campaign/workspace and stale new submissions fail before work.
- Trusted `OfflineRoute(manifest_path, version="offline-fixture-v1", limits=RunLimits(max_requests=10, max_pages=10, max_records=10))` configures only `fixture-json` with `synthetic: true`. Limits are immutable positive integers with hard maxima of 100 requests/pages/records and 10 MiB; manifests are at most 1 MiB/100 items. Defaults retain 1 MiB bytes. The configured input references remain unverified source pointers.
- Submission reads configuration without collecting payloads. Before acknowledgment it commits task/request identity, workspace, initiating human/automation actor, campaign/brief/version, scope/configuration version, purpose/references, manifest hash/path, exact limits, one-attempt bound and queued state. Identical concurrent retries return one task. Changed scope, configuration, limits or producer under that identity conflicts. Retries retain the original basis after a successor campaign brief; a new stale-brief submission fails.
- `OfflineTaskWorker(db, evidence_root, workspace_id="local").run_one(task_id, automation_actor)` executes at most one queued task using the existing `IngestionRunner`. It persists the attempt identity, actual automation worker, ingestion run and collecting phase first. Its registry contains only the local JSON fixture collector/mapper. Changed manifest input fails before collection; the runner independently verifies its persisted manifest digest. No source/model/paid call is available in this task path.
- `read(task_id, actor)` reopens exact scope/attribution, limits, attempt/run/producer identities, phase history, actual resource/count coverage, sanitized failure phase/code and publication links after restart. `list(actor)` returns the newest 100 workspace acknowledgments. No copied source payload/value is stored with the task. Publication/query owners reapply current policy to values.
- Outcomes distinguish queued progress, `usable_update`, `no_usable_update` and `failure`. Counts distinguish collected/persisted observations, applied ingestions, quarantines and actually published source members. Fetch/normalization/permission/limit failure cannot claim a KB benefit. Empty input and normalized records without eligible identity/support create no publication or market-absence assertion. Terminal worker retries return the same outcome, run and publication without collection.
- `KnowledgePublications.unpublished(support, actor, include_synthetic=False)` compares candidate captures/mappings with currently usable published support. `IngestedEvidence.read` exposes a one-way source-owned `content_version` binding payload/provenance/capture/source-as-of/method/selected logical fields and metrics independently of run UUIDs. The publication owner indexes this identity, lazily fills permitted legacy metadata through public source reads, and requires current process policy/current derivation health on both sides. The same published capture produces no new task publication; a later capture/mapping or newly usable permitted source can publish. This does not claim general semantic deduplication, market novelty or freshness.
- CLI: `submit-campaign-task CAMPAIGN_ID --brief-id BRIEF_ID --purpose TEXT --request-id ID --offline-manifest PATH [--offline-route-version VERSION] [--actor NAME]`; `run-offline-task TASK_ID [--worker-id NAME]`; `inspect-task TASK_ID [--actor NAME]`. Worker execution uses persisted configuration, not a caller-selected collector. Failed worker outcomes exit nonzero. `migrate` installs the task schema after ingestion/knowledge/campaigns.
- Local HTTP: configure the server with `smi-review --offline-manifest PATH`; campaign pages link `GET /campaigns/ID/tasks/new`, same-origin/CSRF-protected `POST /campaigns/ID/tasks`, `GET /tasks` and `GET /tasks/ID`. Submitted authority/route fields are rejected. The server records its configured named human. Detail pages reopen without route configuration and link synthetic publications using explicit `?include_synthetic=yes`; publication values are escaped/current-policy reads.
