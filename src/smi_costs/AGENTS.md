# Offline usage accounting and synthetic admission

Own immutable cost scopes, attributable stable operations, append-only accounting entries, trusted scope ceilings, immutable synthetic worker-route bindings and one-use dispatch reservations. Public boundaries are `CostScope`, `UsageAccounting`, `SyntheticOperationAdapter` and `SyntheticResult`. Read [the contract](../../docs/costs.md) before changing rates, scope totals, identities, dispatch, settlement or uncertainty; read [ADR 0006](../../docs/adr/0006-bounded-synthetic-admission.md) before altering concurrency or recovery.

Keep dependencies toward shared database/actor/error contracts. Validate exact task/attempt attribution through an injected public resolver. Accounting imports no task code and reads no task tables; task execution composes the public adapter on its own fenced session. Retain source-free actor/method/service/rate/currency/period/provenance metadata; keep source values and responses with their owners.

Serialize every relevant ledger write and admission decision on the scope row. Calculate allowance over all operations, independent of newest-100 presentation lists. Count every legacy append-only declaration indefinitely; usage retires only its own adapter reservation. Unknown/meter-failure coverage blocks metered dispatch. Commit one bounded reservation before I/O, settle usage and reservation together, and retain commitments on loss. A retry never receives another execution grant from a dispatched/settled identity. Hold transactions outside I/O and join a caller-supplied task transaction for actual dispatch/settlement effects.

Use finite exact decimal inputs/products/totals and immutable scope/rate configuration. Keep forecast-only scopes without monetary claims and retain independent request/record/byte limits. Trusted human configuration stays outside form/assistant payloads. Persisted route bindings apply across recovery. The adapter enables bounded simulated service contracts only; delayed billing and ambiguous reconciliation require a later explicit contract.

Verify public operations/HTTP with real PostgreSQL, genuine competing workers/processes and counted fake I/O. Cover refusal with zero calls, identity reuse, old liabilities, unknown coverage and session-loss boundaries. Update contracts, architecture, physical ERD and dictionary together.
