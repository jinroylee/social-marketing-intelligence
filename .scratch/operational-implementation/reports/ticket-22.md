## Delivered

- `ScheduledPostAllowance` within the existing `smi_tasks.schedules` owner coordinates `scheduled_post_days` and per-observation `scheduled_post_admissions`. One fixed workspace/accounting-day row serializes unique-new-post admission across all registered keywords and competing workers, independently of request/record/cost limits. The initial configurable total is 50 across at most ten keywords.
- The public `CanonicalAdmission` protocol joins `IngestionRunner.resume` and `CanonicalWriter.apply` on the existing fenced `TaskExecution.transaction` connection. Current process-policy validation and normalization precede admission. Canonical identity locks establish whether the normalized source content is already known. Admission and canonical entities/derivations/source status commit or roll back together, before any excess canonical writes. No database transaction spans collection/normalization and no detached reservation survives failure.
- Exactly one stable platform/namespace/native/synthetic content identity is required per record. Successful previously unknown identities debit `new_posts`; first known observations record `known_refreshes`, and identities already admitted/refreshed that day record `deduplicated_posts`. Both refresh categories may apply legitimate observations without another debit. Limit-excluded or identity-ineligible records retain evidence/checkpoints with explicit `skipped` status and no canonical derivation/publication support. Malformed and process-denied records keep existing failure/quarantine behavior and consume no new-post admission.
- Configuration changes update the current recorded day's effective cap/version without resetting used identities. Raising opens capacity; lowering below used preserves usage with remaining zero. Keyword edits/removal/re-registration, new keys and restart never reset consumption. Delayed tasks retain their original day. Historical task scope, including old enforcement markers, remains immutable; current effective enforcement is separately exposed. Upgrade/day bootstrap selects the latest configuration recorded before the fixed day end, serializes with schedule configuration and advances cap versions monotonically, preventing an older queued context from regressing the cap. Pre-enforcement usage is not invented retrospectively.
- Schedule/task public reads and HTTP views show actual shared used/remaining/cap/version, aggregate and per-occurrence new/refresh/dedup/excluded/ineligible counts, immutable authority, independent limits and honest fewer-record outcomes. Empty or entirely excluded results can finish `no_usable_update`; legitimate new observations and existing partial/failure/publication semantics remain distinct. There is no promise of fill, per-keyword yield or market completeness.
- Preserved configured actor/scope authority, approval boundaries, cost admission and uncertain no-reissue, session fencing, exact prepared support/publication receipts, current policy and recoverability. The worker remains bounded/offline; no daemon, provider fallback or monetary extension is introduced.
- Updated glossary, task/architecture/HTTP/reader contracts, physical ERD/table dictionary, stable-day ADR and new durable ADR 0012. Updated ingestion/task/schedule/review module guidance; existing relative `CLAUDE.md -> AGENTS.md` siblings remain the single source of truth.
