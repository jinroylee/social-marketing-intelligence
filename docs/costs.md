# Attributable offline cost accounting

The installed `smi_costs` owner records synthetic measured usage, derived synthetic amounts, forecasts, declared outstanding commitments and explicit uncertainty. Its public `UsageAccounting` operations use real PostgreSQL and trusted workspace/actor contexts. Bounded synthetic admission and the fixture worker meter are installed. They make simulated local calls only, with no commercial charges or live provider/model enablement. [Hybrid spending control](functional-requirements.md#hybrid-spending-control) retains commercial metering and provider-specific reconciliation as future work. Explicit delayed synthetic reconciliation and meter recovery are installed below.

## Configuration and attribution

`UsageAccounting(db, workspace_id='local', task_attribution=resolver)` owns eight tables and has an independent idempotent `migrate()`. `smi-ingest migrate` installs it. `configure_scope(CostScope(...), human_actor)` requires a workspace human operator and persists an immutable workspace/scope identity. Configuration includes provider, service, `metered` or `forecast_only` classification, uppercase three-letter currency code and an explicit timezone-aware accounting interval. The interval is start-inclusive and end-exclusive, normalized to UTC. Currency codes are operator declarations; this module performs no exchange conversion or currency registry lookup.

A metered scope additionally requires unit, rate version and exact nonnegative unit rate. This milestone supports only **synthetic** metered configuration: the public scope document explicitly marks that basis. Rates are supplied by the operator for simulation, not retrieved commercial prices. Forecast-only scopes accept no meter/rate fields. Missing configuration fails; meter failure cannot reclassify the scope. Changed rate, period, currency or classification under an existing identity raises `cost_scope_conflict`; use a new scope identity for new configuration. The original operator and configuration time remain readable.

`begin_operation(scope_id, actor, request_id=..., method=..., task_id=None, attempt_id=None)` commits an operation before a meter result. Workspace/request identity pins scope, actual actor/kind, method version and optional exact task/attempt. Identical concurrent retries retain one UUID; changed reuse raises `cost_operation_conflict`. Method and service identify equivalent operations, including synthetic model operations with no acquisition task. No-task attribution still requires an actor, method and stable request identity.

Task and attempt must be supplied together. Task-linked operation creation requires an injected public resolver with `(task_id, attempt_id, actor) -> {'task_id': ..., 'attempt_id': ...}`. `AcquisitionTasks.resolve_cost_attribution` normalizes IDs, reopens the task through its public workspace boundary and verifies exact attempt membership. Foreign/nonexistent tasks or foreign/unrelated/nonexistent attempts are rejected. Accounting neither queries task tables nor imports the task package. Task execution composes this public accounting owner and the task attribution resolver; dependency direction stays acyclic. The local application composes these owners. Persisted task references are public-owner-validated logical references, without a cross-owner SQL foreign key. Historical accounting reads remain independent of source payload permission, publication availability and task route configuration.

## Measurements and nonactual records

`record_usage(operation_id, actor, measurement_id=..., units=..., rate_version=..., measured_at=..., provenance=...)` derives `units × configured unit_rate` exactly. It rejects forecast-only scopes, wrong rate versions and measurements outside the accounting interval. Entries retain units/unit, exact rate and version, derived amount, timezone-aware measurement time, source-free measurement provenance, actual recorder and database recording time. These are synthetic measurements, explicitly **not commercial charges**.

Numeric inputs accept decimal strings, `Decimal` or integers, with values from zero through `10^18`, at most 12 fractional places and exponent from −12 through 18. Floats, booleans, negatives, invalid/nonfinite values and unsupported precision fail before recording. Products/totals use a separate 80-digit decimal context and canonical decimal strings; no binary float or rounding to currency minor units is introduced. An explicit measured zero is distinct from missing measurements.

The following operations keep distinct entry kinds:

| Public operation | Meaning |
| --- | --- |
| `record_forecast(..., amount, currency, measured_at, provenance, assumptions)` | Additive estimate for this operation with explicit assumptions, available for either classification |
| `record_commitment(..., amount, currency, measured_at, provenance)` | Declared outstanding synthetic amount for a metered operation; observational only, with no reservation/admission |
| `record_uncertainty(..., state='unknown' or 'meter_failure', measured_at, provenance, reason)` | Durable unknown coverage or expected-meter failure; no invented monetary amount |

All records require a stable `measurement_id`, unique across the workspace, not just within an operation. Identical content/recorder/kind/operation retries reconcile once, including concurrent calls and after restart. Changed reuse raises visible `cost_measurement_conflict` and preserves the original record. Normalized operation UUID spellings retain the same identity. No entry is silently overwritten. Forecast and commitment identities represent independent additive portions, not replacement estimate revisions. They never become actuals because a usage record arrives. Declared commitments remain outstanding until named by an explicit final reconciliation; independent usage arrival alone does not reduce their amount.

## Reads and local detail

`read(operation_id, actor)` returns immutable configuration/attribution, exact entries and separate `actuals`, `forecasts` and `commitments` totals. An absent category has `amount: null`, rendered **Unknown**, rather than zero. Actuals explicitly report `synthetic: true`, `commercial_charge: false`; `enforced_monetary_control` reports whether this exact metered scope has a configured synthetic ceiling; the separate admission state records whether this operation was actually dispatched through the guard. Entry totals combine only entries of the same operation, configured currency and period. `allowance` separately reports full authoritative scope totals, without the list presentation limit. No cross-currency or period total is invented.

Coverage states distinguish `unmeasured`, `synthetic_measured`, `forecast_only`, `unknown` and `meter_failure`. `unknown_cost` remains true for forecast-only/missing measurements and outstanding commitments, dispatched reservations or unresolved uncertainty. A measured amount is the known portion. Reconciliations and meter recoveries change the active coverage state while original unknown/failure entries remain readable. Final usage alone does not restore a failed meter. Configuration classification stays fixed.

`list(actor, task_id=None)` returns the newest 100 workspace operations; older operation identities remain directly readable. A task filter selects accounting metadata without asserting task existence; callers needing an existing task reopen it through `AcquisitionTasks` first. Every read/write checks workspace. Accounting stores source-free operational metadata, never source payload, captions, URLs, prompts, responses, credentials or unrestricted explanations. Callers supply sanitized provenance/reason/method identifiers. Revoking source support therefore does not erase measured historical resource usage or expose denied source values.

**Costs**, `GET /costs`, `GET /costs/OPERATION_ID` and task detail's `GET /tasks/TASK_ID/costs` use these public interfaces. The task route reopens the owning task first. Pages escape metadata, show exact attribution/provenance, separate amounts, synthetic basis and the exact configured monetary-control state. Missing records establish unknown coverage. Task detail additionally reopens the current cost-control summary independently of its saved waiting progress. Configuration, recording, final reconciliation and meter recovery remain trusted Python operations; no browser form can configure a rate, assert a measurement or grant spending authority.

## Extension boundary

Existing source/model tools receive no live monetary authority from accounting. Declared commitments and uncertain calls require the explicit final-evidence operations below; there is no automatic timeout release, write-off or forecast fallback. The bounded newest-100 list is presentation only; admission below reads the full scope. A pending synthetic declaration is not proof that a remote call was safely bounded or free. The original synthetic adapter enables the bounded fake-service contract only. The separately configured provider Responses route below extends this ledger with verified model input/output bounds and explicitly distinct provider-reported provenance.


## Shared bounded synthetic admission

`configure_ceiling(scope_id, human_actor, amount=..., currency=..., period_start=..., period_end=..., paused=False)` configures trusted server control for an existing metered scope. Currency and the UTC start-inclusive/end-exclusive interval must exactly match that immutable scope. Amounts use the same finite exact decimal validation as measurements. Only a workspace human operator can set or pause a ceiling; task approvals, assistant text and forms confer no control authority. The operator can change the ceiling or pause state, including lowering it below existing liabilities; existing obligations remain and available allowance is then zero. Forecast-only scopes reject ceilings.

`allowance(scope_id, actor)` reads every operation in that workspace/scope, including identities older than the newest-100 presentation list. It exposes currency/period, classification, ceiling, known measured actual amount, all outstanding amounts, the unresolved declared-commitment subtotal, available amount, actual over-ceiling amount and blocked reason. The admission calculation is:

```text
available = max(0, ceiling - all measured usage - unresolved declared commitments - dispatched reservations)
```

Append-only `commitment` entries remain liabilities until explicitly reconciled. Independent usage never retires them. Unresolved `unknown` coverage or a failed expected meter blocks new metered dispatch as `cost_coverage_unavailable`, even after late known usage or a ceiling increase. A failed meter requires final accounting and a separate operator recovery attestation. Missing required control is `cost_control_missing`; an operator pause is `cost_scope_paused`; an insufficient bound is `cost_allowance_exhausted`. Inactive accounting periods refuse as `cost_accounting_period_inactive`. No unknown monetary coverage becomes a free allowance.

`SyntheticOperationAdapter(accounting, scope_id, max_units=...).execute(actor, request_id=..., method=..., call=..., task_id=None, attempt_id=None, transaction=None)` is the public simulated-operation port. `call(bound)` is a trusted **bounded fake service contract**: one invocation returns `SyntheticResult(value, measured_units)` within the finite declared unit bound and never hides retries/additional requests. The adapter derives the maximum charge from the immutable rate before dispatch. A unit-bound mismatch on an existing operation conflicts. The callback is never invoked on `refused` or `paused` results. Only an `executed` result contains the transient value; accounting stores no service response, prompt, payload or source value.

One scope row serializes ceiling decisions, declared commitments, uncertainty, independent `record_usage` writes, reservation changes and usage settlement across real connections/processes. No transaction spans service I/O. Admission first commits one `cost_admissions` row in `dispatched` state. Exact allowance is sufficient. Concurrent retries see this row and pause as `cost_operation_in_flight_or_uncertain`; they cannot share its permission to execute. Successful bounded results atomically append one synthetic usage entry and change the reservation to `settled`, replacing the full reservation with measured actuals without double counting. A settled identity pauses as `cost_operation_already_executed`; a fresh request identity represents a distinct operation, never a retry. Refused identities can retry after the operator fixes control, preserving the operation's attribution and bound.

Exceptions, meter-contract violations, process death and lost acknowledgments retain a dispatched reservation. An invalid/out-of-bound meter result additionally records meter failure and blocks further metered scope dispatch: the advertised bound is no longer established. A late result cannot settle through a lost task ownership session. Even a successfully settled result may be unavailable to task ingestion after a later crash; recovery pauses that dispatch rather than inventing provider-side replay or another paid call. There is no automatic timeout/release or remote response recovery. Explicit final-evidence synthetic reconciliation below can settle supported liabilities; it cannot recover the transient response or authorize another call. Reported independent actuals remain recordable even when they exceed the ceiling: truthful historical recording is not a new execution grant. Recording those writes under the scope lock prevents subsequent decisions from reading stale committed spending; it cannot undo spending outside the guarded fake service contract. See [the admission decision](adr/0006-bounded-synthetic-admission.md).

### Trusted worker binding

`configure_route('fixture-json', scope_id, human_actor, max_units='1')` persists an immutable workspace/route binding to an existing metered or forecast-only scope. This installed route contract bounds each collector invocation to one synthetic request, including no-item waits. A changed scope/bound conflicts. Configure this before enabling the controlled simulation. Neither the task payload nor a worker recovery argument can omit or replace the binding. `route_control(adapter_id, actor)` reopens it after process restart. Task migration installs the accounting schema; CLI migration remains independently idempotent.

The worker always reopens this binding and wraps its actual collector dispatch, for both campaign and exact approved-assistant origins. The checkpoint digest plus task identity pins one operation across recovery; operation attribution retains the original attempt producer, and dispatch/measurement retain the actual worker. The injected task resolver validates the exact real task/attempt. Admission and settlement use `TaskExecution.transaction` on the ownership connection; existing evidence, canonical, publication and completion fencing remains intact. Refusals become nonterminal task `waiting` progress containing reason, operation identity, allowance and resumability. No completion event claims a finished task while it waits. Approval, publication/shortlist saving and future trusted origins grant no alternative dispatch route.

Forecast-only bindings execute with no monetary ceiling or actual-cost derivation. Their one-use operation identity still prevents repeated calls under one dispatch; the runner independently enforces request, record and byte limits. The unbound default `fixture-json` route remains the original purely local file-read workflow, with no declared metered service; installing a binding enables the guarded simulation for all workers of that workspace. This does not enable any real paid route, model or provider.

For a trusted local operator, configuration is through the public Python boundary (no browser control form):

```python
costs.configure_scope(CostScope('simulation-oct', 'synthetic-local', 'fixture-simulation',
    'metered', 'USD', '2026-10-01T00:00:00Z', '2026-11-01T00:00:00Z',
    unit='request', rate_version='simulation-v1', unit_rate='0.125'), operator)
costs.configure_ceiling('simulation-oct', operator, amount='1', currency='USD',
    period_start='2026-10-01T00:00:00Z', period_end='2026-11-01T00:00:00Z')
costs.configure_route('fixture-json', 'simulation-oct', operator, max_units='1')
```

These are explicitly supplied simulation figures, not a researched commercial rate. Cost detail shows **Enforced synthetic monetary ceiling** only with configured metered control, plus exact scope allowance and operation admission status. Forecast/uncontrolled details retain **No enforced monetary ceiling**, and every detail retains **No commercial charge**.

## Final synthetic reconciliation and meter recovery

`reconcile_usage(operation_id, human_actor, reconciliation_id=..., measurement_id=..., units=..., rate_version=..., measured_at=..., provenance=..., reconciled_at=..., evidence_id=..., outcome='succeeded' or 'failed', settle_admission=False, commitment_ids=(), uncertainty_ids=())` records one exact final synthetic measurement and resolves only the explicitly named cost portions, in one scope-locked transaction. The operator attests an identified final report, its sanitized provenance and final service outcome. These trusted simulation inputs are not independently verified commercial billing. A failed call can have nonzero usage; releasing its whole bound requires an explicit final measured zero. An ambiguous, pending, timed-out or merely retried call supplies no final evidence. No bounded write-off policy is installed.

At least one target is required. `settle_admission=True` names this operation's still-dispatched reservation. `commitment_ids` names independent declaration entries; `uncertainty_ids` names unknown/failure entries whose cost portion this final report covers. Each target must belong to this exact operation, match its required kind and still be unresolved. Lists are canonical sets of at most 200 distinct identities each. A report covering several named portions settles that group once; it cannot later be allocated to another portion. Unnamed declarations, reservations and uncertainties remain active. Resolved declarations contribute zero to current outstanding totals while their original entries retain full amounts. Forecasts are retained unchanged.

The final usage uses the original immutable scope currency, accounting interval and rate/version, including after that period closes. `measured_at` is the attributable usage measurement time within that period; `reconciled_at` identifies the later final-report attestation and can be outside it. The attestation cannot predate the measurement or any target uncertainty/declaration. Actual usage remains recordable above its reservation or ceiling; available allowance floors at zero and `over_ceiling_amount` reports the excess. A late report never rewrites a rate or disguises overage as a forecast. A final report above its admitted unit bound itself appends a stable expected-meter failure, even if the lost callback never reported one. That derived failure is included in the report’s cost resolution while its health state remains active until explicit recovery; all original failure observations remain independent and readable.

Workspace-global `reconciliation_id` binds the operator, exact targets, final measurement, evidence, outcome and times. Identical replay returns `duplicate` after thread/process restart. Changed identity reuse raises `cost_reconciliation_conflict`; changed final measurement facts raise `cost_measurement_conflict`. A target already settled by another event rejects the new report before creating its usage. Each final `measurement_id` can be allocated to only one reconciliation in the workspace. An already recorded usage entry with exactly equal facts can be linked without adding an amount or replacing its original recorder; the reconciliation retains its separate operator. Independent `record_usage` remains additive for independent portions and does not identify a final settlement; route final bills through `reconcile_usage`.

A reconciled admission remains `settled` forever. Its original dispatch bound/dispatcher and all entries survive; repeated adapter/worker execution pauses without calling transport. If the original still-owned callback returns concurrently, equal measured units reuse the final charge and retain the response; conflicting units raise `cost_measurement_conflict` without adding another charge. The existing task session fences that callback's local effects after disconnection. Reconciliation writes accounting only: missing evidence, task completion, source policy and receipted publication recovery remain with their existing owners. A task can therefore remain waiting after its cost has been reconciled.

`recover_meter(operation_id, human_actor, recovery_id=..., failure_ids=(...), recovered_at=..., provenance=..., evidence_id=...)` separately records an explicit synthetic meter-health check. Every named failure must belong to this operation, already have final cost reconciliation, and remain unrecovered. Recovery time cannot predate that reconciliation or failure. Workspace-global identity makes exact replay idempotent; changed reuse raises `cost_meter_recovery_conflict`. It clears only those named health failures, releases no liability and changes no classification, rate, ceiling or operation grant. Other/new failures still block the scope. Both final accounting and health recovery share the admission scope lock, so racing admissions observe a complete committed state.

`read` exposes immutable `entries`, `reconciliations`, `meter_recoveries` and exact active `unresolved` identities. Its `limits` reports the original declared unit/charge bounds only for an actual adapter admission and their status (`declared`, `unverified`, `within_bound`, `violated` or `not_recorded`), independently of billing state (`awaiting_final_measurement`, `final_measurement_recorded`, `no_final_report_recorded` or `forecast_only`), the unknown `billing_lag_bound`, meter health and enforcement basis. No finite final-report deadline or automatic liability expiry is established. Final billing can be complete while meter health still blocks the scope; a violated historical bound remains visible after health recovery. A declaration is not a proven bound. Cost detail and relevant task detail display known charge bounds, current billing lag/state and the strict-enforcement limitation: **No zero-overshoot guarantee for delayed or unbounded charges.** Every amount remains synthetic and every detail retains **No commercial charge**.

## Responses token measurement and provider provenance

Campaign interpretation and supported ranking use the existing scope-locked, one-use admission/settlement ledger. It adds `ProviderOperationAdapter`/`ProviderResult` alongside the unchanged synthetic port. `CostScope.measurement_basis` defaults to synthetic and is omitted from default stored documents, preserving historical configuration/retry identities. Explicit `provider_reported` scopes are metered, retain `synthetic=false` and cannot execute through the synthetic adapter. The campaign route additionally requires provider `openai`, service `responses`, `weighted_token` units and its exact rate version. No browser field grants configuration authority.

The campaign attempt owns a logical cost-operation reference without cross-owner SQL foreign keys. It retains exact model/weight/bound configuration and requesting-human/brief linkage for criteria and actual automation/brief linkage for ranking. Accounting stores the model automation actor, method, scope/rates, finite reservation and source-free reported input/output/total/cache-read/cache-write/reasoning counts. Its provider entries identify `provider_reported` measurement and provider-usage provenance. Prompts, original prose, raw responses and credentials are absent. Provider-reported units valued at configured rates are **not** independently verified invoices; `commercial_charge` remains unknown. Reads and HTTP distinguish these values from synthetic measured amounts.

Weights are explicit trusted server configuration, with no default commercial rates. Under the model route's standard-tier policy, cached reads and remaining input use their configured weights; cache writes remain an input detail priced as uncached input. All reported generated output is counted, including nonvisible formatting/reasoning tokens; reasoning is an included detail, not an additive charge. Counts, total equality, cache partitions, reasoning subset and finite model bounds are validated before settlement. Synthetic fixtures may explicitly declare another cache-write weighting policy. Missing detail, model identity mismatch, nonfinal/unknown status, unsupported terminal status or returned-tier mismatch cannot establish final supported usage/rates and never settle a partial count as the whole call.

Admission reserves `max_input_tokens × max(input/cache-read/cache-write weights) + max_output_tokens × output_weight` weighted units. Accounting describes only its generic declared bounded-provider contract premise; exact model verification remains with the shared campaign Responses route configuration. Provider mode pins the official snapshot's maximum input and a configured generated-output cap with truncation disabled; simulated mode relies on its separately labelled fake-service declaration. One transport invocation occurs after admission commits, with no database transaction across I/O. Valid final usage settles unusable/refused/incomplete/stale interpretations and ranking assessments too. Invalid/unknown metering retains the dispatched reservation and fails the expected meter; HTTP error/redirect/timeout/loss retains uncertain consumption. There is no automatic zero, retry, liability expiry or cancellation/billing-lag guarantee.

The existing human-only `reconcile_usage` and `recover_meter` boundaries accept explicit `measurement_basis='provider_reported'` for a provider scope. Default synthetic attestations cannot settle or recover provider records. Final operator evidence retains exact original scope/rate/currency/period, outcome, named liabilities and attestation time; the entry identifies operator-final-report provenance and `synthetic=false`. This is a trusted attestation, with `commercial_invoice_verified=false`, not an invoice API or fabricated independent proof. Known actuals remain reportable above the admitted bound/ceiling. A bound violation creates a separately recoverable meter failure; final cost settlement alone does not clear meter health. Separate explicit provider health attestation clears only already-reconciled named failures. Replays/conflicts, source-free evidence and one-use/no-reissue invariants remain the same as synthetic reconciliation. Reconciliation restores neither a missing interpretation/ranking response nor task authority.
