# Quantitative X alert history

Own `QuantitativeAlerts`, `VolumeThreshold`, immutable assessments, exact request receipts and atomic retained alert/local-notification identities. Read [the quantitative contract](../../../docs/monitoring.md#configured-quantitative-volume-assessments) and [ADR 0019](../../../docs/adr/0019-source-free-quantitative-alert-history.md) before changing comparison, retry, source lifecycle or inbox behavior.

This owner implements one distinct-native-post sample-volume threshold. Require an explicit operator configuration and exact detection/baseline window IDs. Persist missing/incomparable/partial-support limitations; compare only complete compatible nonoverlapping equal-duration samples. Deduplicate native posts across captures. A zero/inadequate baseline has no ratio. Threshold crossing is a configured synthetic sample signal, not independent statistical proof or market completeness.

Consume `RecentMonitoring.require_operator` and `read_window_in_transaction` on the same local connection as assessment/request/alert writes. That owner owns its SQL, reconciliation and workspace policy lock; retain the lock through commit. Perform no external I/O in the transaction. Depend only on recent evidence, trusted actors and PostgreSQL; the separate `../semantic/` owner handles provisional model positions; KB explanation, promotion, external searches and campaigns are outside this interface.

Store source-free method/configuration, window references, historical outcome/limitations, actor/time and retry identities. Display current counts and evidence only from the exact original windows with current process/display/retention permission. Apply this stricter alert permission overlay to every returned nested window body and its availability state, including history and dependent HTTP/context views; standalone recent display reads retain their own purpose policy. Withhold the whole quantitative comparison when any support is unavailable; preserve original alert identity and honest tombstones. Source copies in notification/assessment tables or recomputing history from newer windows would bypass this lifecycle.

Keep pair/configuration deduplication independent of request identity. Exact request retries require the original inputs/configuration/actor/workspace; new requests for a saved pair reopen its first outcome. Bound retained assessment/request counts and latest-100 lists; exact reads outlive those lists. Compose notifications into the browser inbox through this public owner rather than creating task events or querying task tables. Test public poll/detect/history/alert/inbox/HTTP operations with real PostgreSQL, simulated source/time and fault-only DDL for commit/concurrency failures.

`read_alert(..., connection=...)` accepts the caller-owned local transaction for dependent context commits; retain the recent policy lock through it. The separate `../context/` owner composes existing-KB explanation; this detection owner keeps its own SQL and grants no new acquisition or model authority to context readers.
