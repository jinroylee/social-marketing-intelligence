# Shared bounded Responses dispatch

Own the concrete OpenAI Responses route, disabled-by-default HTTPS transport, envelope/usage checks and shared monetary admission/settlement. Criteria interpretation and supported ranking supply their bounded request and independent output validator; they retain their own persistence and domain decisions. Read [the provider contract](../../../docs/costs.md#responses-token-measurement-and-provider-provenance) and [campaign behavior](../../../docs/campaigns.md) before changing dispatch.

Preserve the verified exact snapshot, explicit rates/configuration, fixed TLS endpoint, one POST, no tools/state/retries/redirects, finite bytes/deadline/output bounds and conservative admitted input contract. `ResponsesTransport.create` and the HTTP connection factory are simulated external-I/O seams. Match provider/synthetic measurement basis, final model/status/tier and token/cache usage before settlement. Retain uncertain liability; raw responses, prompts, credentials and exception text stay out of cost or attempt records. A domain validation failure can still consume billable usage.

Expose only this concrete shared transport seam. New domain schemas/SQL belong to their campaign owner; this module grants no campaign, acquisition or approval authority. Preserve criteria public import compatibility when moving implementation.
