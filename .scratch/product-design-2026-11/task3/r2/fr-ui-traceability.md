# Functional-requirement UI traceability, r2

This matrix maps every stable ID in the authoritative [Task 1 recovery matrix](../../task1-recovery/requirements-matrix.md) to the reviewed-design proposal. Source targets and source implementation status are retained verbatim as traceability metadata, not independently rerun readiness claims. The [design specification](design-spec.md) defines C1/K1/A1/G1/M1/M2/T1/D1/S1/P1 read models and command needs. These are owner interfaces or future adapter needs, not installed HTTP endpoints.

Coverage labels distinguish interactive fixture paths, specified extensions and future proposal work. A global fixture notice applies to every prototype click. No click proves a backend capability, live source, recurring worker, commercial meter, email transport or semantic method is installed or accepted.

Validation references M01–M11 are [manual review scenarios](review-guide.md) and remain pending actual browser/human execution. Source checks refer only to the minimal Node element-stub fixture checks in [verification-results.txt](verification-results.txt), not browser or full-stack tests. Browser preview was declined; screenshots, keyboard behavior and responsive rendering remain unverified. Real backend acceptance remains required for every owner boundary.
