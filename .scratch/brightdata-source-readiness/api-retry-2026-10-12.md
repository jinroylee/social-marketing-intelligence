## Adapter correction and offline replay

The retained responses exposed an identity-schema difference from the previous documented examples: the profile's `account_id` contains the handle and `id` contains the native ID; posts use `profile_id` for the author. The original mapper expected numeric `account_id` and `author_id`, producing one unresolved profile and ten missing author links despite successful HTTP responses.

[The Bright Data adapter](../../src/smi_ingestion/adapters/bright_data.py) now resolves both current and legacy identity fields, rejects conflicting author IDs, and keeps numeric handles distinct from native IDs. Collector checkpoints use the same profile identity resolver. Mapper version `v2` allows replay to supersede the prior interpretation without overwriting its history.
