# Requirement to implementation trace

This is a planning reference, not an implementation or readiness score. It covers all 99 stable upstream IDs and three r2 review IDs. Read each assigned spec's full acceptance section, not only its first linked check.

Approved UI authority is [actual r2 approval](../.scratch/product-design-2026-11/ui-review-status.md#actual-r2-approval), which supersedes historical pending language inside the frozen [r2 UI mapping](../.scratch/product-design-2026-11/task3/r2/fr-ui-traceability.md). Accepted target and installed-foundation text come from the [Task 1 recovery matrix](../.scratch/product-design-2026-11/task1-recovery/requirements-matrix.md); code evidence and spec paths are added here. UI-gap text describes production work needed even when the fixture demonstrates it. Capability-gap cells name the concrete missing or adapted outcome, not an assertion that the installed foundation is absent.

For each row, the contract column is the approved UI's owner/read/command need. The linked spec supplies proposed signatures, fields, migrations, authority and every acceptance check. S05, S31, S08, S25, S35 and S38 require actual operator/human evidence. Later proposal paths preserve full destination coverage without making every ambition a pilot release gate. UD-09's design gate is already satisfied.
