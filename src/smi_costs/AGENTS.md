# Offline usage accounting and synthetic admission

Own immutable cost scopes, attributable stable operations, append-only accounting entries, trusted scope ceilings, immutable synthetic worker-route bindings one-use dispatch reservations, explicit final reconciliations and separate meter-health recovery records. Public boundaries are `CostScope`, `UsageAccounting`, `SyntheticOperationAdapter`, `SyntheticResult`, `ProviderOperationAdapter` and `ProviderResult`. Read [the contract](../../docs/costs.md) before changing rates, scope totals, identities, dispatch, settlement or uncertainty; read [ADR 0006](../../docs/adr/0006-bounded-synthetic-admission.md) and [ADR 0007](../../docs/adr/0007-final-cost-evidence-and-meter-recovery.md) before altering concurrency, final evidence or recovery.

Keep dependencies toward shared database/actor/error contracts. Validate exact task/attempt attribution through an injected public resolver. Accounting imports no task code and reads no task tables; task execution composes the public adapter on its own fenced session. Retain source-free actor/method/service/rate/currency/period/provenance metadata; keep source values and responses with their owners.

Serialize every relevant ledger write and admission decision on the scope row. Calculate allowance over all operations, independent of newest-100 presentation lists. Count every unresolved declaration; independent usage retires only its own adapter reservation. Final reconciliation names exact operation-bound liabilities and one final bill, retaining original entries and recorder. Allocate a bill once and reject changed/overlapping settlement before adding usage. Unresolved unknown coverage and unrecovered meter failure block metered dispatch. Commit one bounded reservation before I/O, settle usage and reservation together, and retain commitments on loss. A retry never receives another execution grant from a dispatched/settled identity. Hold transactions outside I/O and join a caller-supplied task transaction for actual dispatch/settlement effects.

Use finite exact decimal inputs/products/totals and immutable scope/rate configuration. Keep forecast-only scopes without monetary claims and retain independent request/record/byte limits. Trusted human configuration stays outside form/assistant payloads. Persisted route bindings apply across recovery. The synthetic adapter enables bounded simulated service contracts only; final synthetic evidence can resolve named delayed/ambiguous costs. Require a human final-report attestation, including explicit measured zero for an uncharged failure, and separate attributable health recovery for already-reconciled meter failures. Keep original rate/currency/period, actual overages and one-use dispatch identities. Reconciliation restores no response, task effect or publication authority; no timeout or forecast fallback releases a liability. Provider evidence verification and bounded write-off policies require another contract.

Verify public operations/HTTP with real PostgreSQL, genuine competing workers/processes and counted fake I/O. Cover refusal with zero calls, identity reuse, old liabilities, late usage/failure, replay/conflict, concurrent settlement/admission, meter recovery and session-loss boundaries. Update contracts, architecture, physical ERD and dictionary together.

Provider scopes explicitly record `measurement_basis=provider_reported`; default synthetic documents keep their historical shape. Admission/settlement remain the same scope-locked one-use ledger. Retain source-free token/cache/reasoning counts and provider provenance; provider-derived amounts are not synthetic or verified invoices. The Responses caller owns verified model/context/output bounds and final model/status/tier validation. Explicit provider-basis operator final reports and separate health attestations reuse exact reconciliation/recovery invariants; default synthetic evidence cannot relabel provider usage. Keep actual overage, unresolved liability and no-reissue behavior visible.

The supplied-reference and offline keyword fixture routes share the one-request synthetic binding contract. Keyword pages return one source record or an empty result per invocation; count actual requests independently of matched/corpus records, preserving reservation/unknown/no-reissue semantics.

`DeferredProviderOperationAdapter` accepts source work without a final bill via `DeferredProviderResult`, retaining its dispatched reservation and no-reissue identity. The live keyword binding requires exact Bright Data/provider basis/service/unit configuration; its enforcement basis is a declared source commitment, not a verified charge cap. Every source HTTP attempt is conservatively admitted, including progress/download; output counts do not settle billing. Explicit provider-basis final reconciliation remains the only settlement path and cannot restore source responses.

The optional `brightdata-tiktok-profile` binding deliberately shares the primary keyword-named declared provider scope; actual method stays profile-specific. Require explicit operator binding and keep final profile charges unknown. A pending or lost profile response retains its admission; the parent task may publish useful primary support while supplementary work stops without reissue.

An optional trusted `dispatch_guard(connection)` runs after the allowance/reservation decision in the actual dispatch transaction. It returns a source-free refusal code or `None`; retained domain locks span admission commit, while external I/O follows commit. Refusal records `refused` with no dispatch liability, usage or meter failure. Keep domain policy inside the injected guard and preserve one-use semantics for previously dispatched/settled identities.
