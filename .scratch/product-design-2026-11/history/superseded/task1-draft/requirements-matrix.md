# Requirements traceability matrix

Analysis date: 2026-11-03. Status: factual baseline; product-review decisions pending.

## Source and status conventions

The analysis IDs below are stable within this design review. They do not replace the source requirements or introduce new accepted requirements. Split IDs preserve independently testable parts of one source bullet. Source references name the original section and line range at the analysis date.

Authoritative sources are [FR.md](../../../../../FR.md), [operational functional requirements](../../../../../docs/functional-requirements.md), [POPOSAL.md](../../../../../POPOSAL.md), [the glossary](../../../../../GLOSSARY.md), and [accepted ADRs](../../../../../docs/adr/). `POPOSAL.md` is the actual filename.

Each row separates target behavior from the documented current software. `Installed bounded` means the owner contract and repository describe an implementation. It does not mean this investigation executed it, obtained a live receipt, or established usefulness. `Partial target` means installed software covers only part of the accepted capability. `Future` means accepted product direction beyond installed bounds. `Readiness pending` names a separate operational or human acceptance gate. No row asserts a currently running service or a completed human review.

The evidence abbreviations in the final column link to the owning contract:

- C: [campaigns](../../../../../docs/campaigns.md).
- K: [knowledge](../../../../../docs/knowledge.md).
- T: [tasks](../../../../../docs/tasks.md).
- M: [monitoring](../../../../../docs/monitoring.md).
- S: [costs](../../../../../docs/costs.md).
- U: [local review](../../../../../docs/local-review.md).
- E: [evaluation](../../../../../docs/evaluation.md).
- P: [planning](../../../../../docs/planning.md).
- R: [roadmap](../../../../../docs/roadmap.md).
- A: [architecture](../../../../../docs/architecture.md).
- I: [interface and acceptance contract](../../../../../docs/implementation-spec.md).

## Traceability checks
