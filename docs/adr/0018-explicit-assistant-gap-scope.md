# Explicit assistant gap scope keeps approval independent

Status: accepted

A saved assistant answer can identify empty published support, missing or ambiguous information, stale captures, or later loss of its support. Model, configuration and accounting failure alone do not establish a knowledge gap. A task-side application composes the answer with the existing exact proposal/approval/task and completion owners; the answer owner remains independent of acquisition authority.

The installed journey generates a fixed gap-purpose template and requires the human to supply exact subjects, one query and a bounded publication window. Inferring executable query scope from arbitrary question or model prose would obscure what is actually approved and add model work to a workflow that already has a bounded keyword capability. The explicit scope costs an extra input step but makes refresh/fill/expansion intent and route/limits reviewable before actual human approval. It promises research within that scope, not that the source can supply an absent field. Scope can exceed scheduled keywords; broader work receives a separate revision and approval.

A source-free durable linkage claims a fresh nested proposal request before proposal save. Owners commit independently, so recovery first reopens the original proposer-bound saved request without current route files. It never silently replaces the saved configuration. Exact human approval and one-task admission remain with the task owner. Completion uses the exact durable task event under current publication policy. Fetched or pending data never answers a question; later explicit questions see usable publications and historical answers retain their original support.
