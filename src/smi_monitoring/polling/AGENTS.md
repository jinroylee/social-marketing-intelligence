# Periodic recent X collection

Own `RecentPolling` activation history, stable topic/end attempts and `LiveXConfig`/`XRecentRoute` for one official recent-search page. Read [the collection contract](../../../docs/monitoring.md#gated-periodic-live-recent-x) before changing authority, retry or time limits and [ADR 0023](../../../docs/adr/0023-bounded-recent-x-poll-authority.md) for response-loss trade-offs.

Compose only the recent owner's public prepare/save transaction ports and the accounting owner's public route/admission/reconciliation interfaces. Keep recent, task, canonical and cost SQL with their owners. Collection has no KB publication, alert detection, campaign or follow-up research side effect. The separate review application reads source-free history and original governed windows.

An exact operator activation pins one topic revision. Default runtime gates disable HTTP; credentials confer no activation, policy or spending authority. One worker invocation attempts at most one due window. Fair ordering lets other topics progress when one waits. Each topic owns one PostgreSQL session advisory lock; all attempt, cost-admission and recent mutations join transactions on that same session. Keep transactions closed across external I/O. A lost session handle cannot reconnect or write stale effects. The trusted `transaction_observer(stage, connection)` is a diagnostic/failure-control seam; it grants no policy or acquisition authority.

Exact topic/end identity outlives activation edits and presentation limits. Reuse the stored occurrence/initiator/cost identity, including refused retries and source responses lost before save. Dispatched, uncertain and discarded attempts never obtain another HTTP dispatch; final billing cannot recover a source response. Explicit deactivation and a successor activation may skip a blocked interval, retaining its original audit record and liability.

Use fixed-host HTTPS, no redirects/retries/expansions, one ten-post page, strict request/response byte limits and incremental `read1` deadline checks. Retain no credential, token, raw error or source wording in polling records. Unknown original capture/measurement times remain unknown; acquisition response identity distinguishes actual calls without inventing source freshness. Current permissions and topic authority are rechecked after shared-cost contention and before saving. The recent owner retains withdrawal, expiry and promoted-copy lifecycle responsibility.

Verify through public activation/run/read and loopback HTTP, real PostgreSQL, fake external HTTP and controllable clocks/failure boundaries. Include genuine concurrent workers, backend loss, admission-policy races, pending/no-reissue, exact bounds, restart, oldest logical identities, final reconciliation and inherited lifecycle.

Source-rate admission locks one route cooldown across workspaces in this installed schema, spacing requests at least two seconds apart; provider quota/reset/429 metadata can lengthen it. Apply the cooldown in the same admission transaction and preserve zero liability on refusal. Other schemas/installations/databases and external shared-app traffic remain outside local quota coordination.
