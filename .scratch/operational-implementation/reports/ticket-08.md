# Ticket 08: durable local task completion inbox

Status: implemented locally; ticket remains claimed for integration verification.

## Installed behavior and public interfaces

- Each worker completion inserts one `task_completion_events` row in the existing `TaskExecution.transaction('completion')` ownership transaction, together with terminal task outcome/coverage, attempt completion and exact task/publication link. The event's unique task reference prevents duplicates. Session loss rolls back the actual event and outcome; a committed completion remains readable without worker acknowledgment. Terminal retries retain the outcome, attempt/run/publication and event identities.
- `CompletionInbox(db, workspace_id='local').list(actor)` returns at most 100 newest completions; `read(event_id, actor)` reopens a retained identity. Messages distinguish usable, partial, no usable update and failure, exposing actual historical published/remainder counts, sanitized failed phase/code and the exact task/publication references. Pre-collection failure now retains its known requested/remaining input count rather than implying unknown scope.
- Inbox storage retains only event identity, task reference and original completion time. Task outcomes remain the immutable source of truth. Every inbox read reopens exact publications through `KnowledgePublications.read` under current display policy. Links are supplied only for publications with some available/current pinned support. Historical outcome/counts remain visible when support becomes unavailable, while current availability and unavailable counts are explicit. No source wording, source URL, task-purpose text, payload or cached availability is copied into events or messages.
- Task migration idempotently backfills pre-inbox terminal outcomes, preserving original finish time (submission-time fallback for legacy missing timestamps), task/attempt/run/publication IDs and original attribution. `reconcile(actor)` inserts only missing workspace terminal events and reports `created_events`, including an old writer completing after migration. Concurrent reconciliation retains one event; queued/nonterminal tasks receive none.
- Browser **Inbox**, `GET /inbox` and `GET /inbox/EVENT_ID` survive application restart without route/input configuration. Marketer-facing messages show compact requested/collected/ingested/quarantined coverage and explicit bounded-input/unknown-market limits, with task and permitted publication navigation. Escaping and existing local Host/Origin/CSRF/error boundaries remain in force.
- CLI `list-inbox`, `inspect-completion EVENT_ID` and `reconcile-completions` use the same public operations in separate processes. `--actor` and `--workspace-id` are trusted operator configuration; the default workspace is `local`. Public mismatched actors are denied, foreign workspace lists/reconciliation are empty and foreign event reads return not found.
- Contracts, architecture, physical ERD, dictionary, glossary, durable ownership ADR, current implementation coverage and local browser/operator documentation are aligned. The dictionary's stale total was corrected to the actual **42 physical tables**, including the new event table. The inbox has focused owner instructions and relative `CLAUDE.md -> AGENTS.md`; existing task/review instructions describe its composition boundaries.

## Limits and following tickets

- Delivery is a durable local inbox read, without read/unread flags, external transport, email, Slack, push or automatic campaign regeneration. Events are retained; the 100-event list bound is presentation only and older identities remain directly readable. No delivery scheduler or message broker is introduced.
- Event/outcome atomicity and task-local ownership cover local database effects, retaining ticket 07's session-disconnect limitations. No provider-side exactly-once request/charge promise or cross-task novelty admission is added. Only synthetic local fixture acquisition is enabled.
- Current source permissions remain with publication/source owners. The event retains source-free historical outcome and counts, rather than rewriting prior completion or caching unrestricted source material. A withdrawn publication's source-free identity remains inspectable in history, with its source-dependent link withheld.
- Operators should migrate before starting upgraded workers; explicit reconciliation handles terminal legacy writers after migration. Neither migration nor reconciliation changes acquisition scope, grants approval or executes a queued task.
- Spending/accounting and later tickets remain outside this change. Automated checks do not establish language interpretation quality, human marketer usefulness or live-route readiness.

Only ticket 08 was claimed. Work stayed offline/local in its isolated worktree, with no push, PR, external message, live provider/model call or root planning-file change. No genuine external blocker remains. Integration validation and resolving the claimed ticket belong to the merger.
