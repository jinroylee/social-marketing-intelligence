# Findings

The approved public seam is submit/read → bounded worker → published query, with real PostgreSQL and simulated local fixture inputs. Runner owns bounded collection and deterministic canonical mapping; task admission freezes the exact campaign brief/configuration digest and limits without reading source payloads. Public smi_tasks owner composes existing ingestion/publication owners; worker registers only fixture-json.

Usable publication is separate from fetching or ingestion. The source owner exposes a one-way content_version for exact capture/mapping/selection; the publication owner detects currently usable equivalents without copying source text. This suppresses false new-update claims across fresh run UUIDs while preserving later captures and restored usable permission. One active attempt remains explicit if interrupted; recovery/partial subsets, claims, approvals, notifications and costs belong to 05–10.
