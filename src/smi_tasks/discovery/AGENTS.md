# Offline discovery history

Own `discovery_history` SQL and `DiscoveryHistory` decisions/read models for the single bounded `offline-keyword-json` route. `DiscoveryPolicy` is trusted operator capture-age and canonical-processing configuration, pinned in new task scope. Read [the history contract](../../../docs/tasks.md#capture-based-discovery-avoidance) and [ADR 0013](../../../docs/adr/0013-capture-based-discovery-avoidance.md) before changing eligibility or time semantics.

Task admission/approval, session execution, receipts and completion stay with the parent task owner. Call history mutations only on the existing fenced `TaskExecution.transaction` connection. Source and publication reads use `IngestedEvidence` and `KnowledgePublications`; issue no foreign-owner SQL. Keep raw payloads, captions, assertion values and copied native identities out of history storage. Persist exact support references; render capture/source identity/method context only through current governed reads.

Compare exact query/subjects/window, pinned input/provider/format, route version, independent limits, actual mapper software and canonical processing revision. A successful no-update retrieval may reference already usable publications, without acquiring their task receipts or claiming a new update. Require complete eligible support for every retrieved record: quota exclusions, invalid rows, failed/partial work and empty/unknown results remain eligible. Every capture must be known, nonfuture and within the explicit age bound. Import, processing, publication and skip times never advance capture time. Preserve older result membership and separate source namespaces/metric definitions.

Record the decision before external I/O, retain it across the same task's recovery and complete history atomically with the terminal task/event. A skip makes no collector/cost dispatch, canonical effects, daily debit or new publication. Explain withheld old input without recreating withdrawn source copies. Recompute current usable-publication links under policy; retain the completion-time links separately from current availability and historical decision/outcome. No transaction spans collector I/O; no policy/configuration is accepted from forms or assistant content. Verify public task/KB/HTTP behavior with real isolated PostgreSQL and simulated source requests, never private methods or SQL outcome assertions.
