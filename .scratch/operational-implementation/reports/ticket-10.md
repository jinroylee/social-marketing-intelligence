# Ticket 10: shared bounded synthetic monetary admission

Status: implemented locally; ticket remains claimed for merger verification.

## Installed interfaces and behavior

- `UsageAccounting.configure_ceiling(scope_id, human_actor, amount, currency, period_start, period_end, paused=False)` persists current trusted control for the exact immutable metered scope/currency/UTC interval. It rejects invalid/nonfinite/inexact inputs, wrong currency/period and nonhuman authority. Forecast-only scopes receive no monetary ceiling. Only explicit synthetic rates are used; no prices were researched.
- `allowance(scope_id, actor)` returns authoritative full-scope measured actuals, outstanding commitments, available allowance, exact currency/period, ceiling/operator/pause metadata and blocked reason. It does not use `list()` or its newest-100 presentation bound. Every existing append-only declared commitment remains a liability after usage arrives. Unknown/meter-failure entries block new metered dispatch. Missing control, pause, inactive period and exhausted allowance are visible refusals.
- Public `SyntheticOperationAdapter(...).execute(...)` and `SyntheticResult` implement the trusted bounded fake service contract. The adapter commits one operation-bound maximum-charge reservation before simulated I/O. Scope row locking serializes competing decisions, independent actual/declaration/uncertainty writes and settlement across real connections/processes. No transaction spans transport I/O. Successful settlement atomically appends one exact synthetic usage entry and settles that reservation; only unused bound becomes available. Stable request/actor/method/task/attempt identities and unchanged unit bounds reconcile once. Dispatched or settled identities never grant another callback invocation.
- Callback exceptions, session/process loss and lost results retain dispatched commitments. Invalid/out-of-bound meter results additionally append meter failure and block remaining metered scope allowance. No timeout, declaration release, delayed billing or ambiguous remote reconciliation is installed. A successful settlement followed by lost task evidence pauses recovery rather than charging again for the unavailable response.
- `configure_route('fixture-json', scope_id, human_actor, max_units='1')` establishes an immutable trusted workspace route binding. The synthetic collector contract accepts at most one request per invocation, including waits. The worker reopens this binding after restart; a recovery caller cannot omit or replace it. Existing unbound fixture execution remains the original purely local file-read workflow, with no declared metered service. Binding a metered scope without a ceiling immediately blocks the controlled simulation before I/O.
- `OfflineTaskWorker.run_one` applies the same adapter at the actual collector boundary for campaign and exact approved-assistant paths. Checkpoint digest plus task identity defines one dispatch; original attempt producer attribution is retained and actual dispatcher/recorder stays separate. The injected public `resolve_cost_attribution` validates exact real task/attempt membership. Admission and settlement use the same `TaskExecution.transaction` session as task/source/publication effects. Accounting has no task import or task-table SQL. Task migration composes the accounting migration in one dependency direction.
- Refused/paused worker dispatch becomes nonterminal `waiting` progress, with reason, exact operation, allowance and resumability. No additional collector call or terminal completion event is created. Fixed control can resume a refused operation with the original attempt/scope/approval. Already dispatched/settled identities remain paused. Future trusted origins receive no alternative collector dispatch path; currently unsupported scheduled origins remain rejected.
- Forecast-only bindings keep no actual monetary derivation or enforced ceiling. The runner's independent request/record/byte bounds remain active. Human task approval, source permission, publication and automatic shortlist persistence grant no alternative spending authority.
- Cost detail exposes operation admission state and authoritative scope allowance, with **Enforced synthetic monetary ceiling** only for configured metered control; forecast/uncontrolled detail retains **No enforced monetary ceiling**. Every detail retains **No commercial charge**. Existing task HTTP detail renders waiting reasons. Forms cannot set cost scope/rates/ceilings or route bindings.

Three additive tables (`cost_ceilings`, `cost_admissions`, `cost_route_controls`) join the existing accounting owner. Architecture, contracts, physical ERD, dictionary, glossary, current product coverage, browser documentation and owner instructions reflect the installed boundaries. ADR 0006 records the durable bounded-dispatch/uncertainty trade-off. Existing relative `CLAUDE.md -> AGENTS.md` instruction links remain valid.

## Limits

- The guard enforces the declared bounded **fake service** contract only. No live source/model/provider is enabled and no commercial amount is asserted. A transport that violates its advertised bound invalidates that premise and blocks the scope; retrospective failure detection cannot undo its external effects.
- Independent measured actual reporting remains truthful even if it reveals spending beyond the configured ceiling. It shares the scope lock so later admission sees committed totals. No zero-overshoot claim is made for unrecorded external spending, delayed/unbounded charges or arbitrary providers.
- There is no automatic release/reconciliation API for old declarations, lost responses or settled responses lost before ingestion. Those identities pause; commitments and explicit uncertainty remain conservative. Immutable route bindings in this bounded milestone have no edit/removal/automatic period-rollover operation. New public synthetic operations can use newly configured scopes; broader worker control rotation remains a separate explicit contract.
- Session ownership cannot cancel an already dispatched call. The existing task fencing protects local commits; one-use admission protects against automatic reissue, rather than promising remote exactly-once billing.
- Tests establish installed software behavior, not human-language or marketer-usefulness quality. Work stayed offline/local with simulated I/O, no push/PR, external messages or additional tickets. No genuine external blocker remains. Integration verification and resolving the claimed ticket belong to the merger.
