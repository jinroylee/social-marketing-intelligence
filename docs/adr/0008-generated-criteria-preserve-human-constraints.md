# Save generated criteria as exact, additive interpretation revisions

Status: accepted

Natural-language interpretation must remain inspectable and attributable without rewriting the marketer's campaign or granting authority from generated text. Save each attempt against one exact immutable human brief and original prose. Its successful executable profile appends namespaced validated criteria to the unchanged structured human constraints. Keep human input, model generation, source facts and acquisition approval as separate contracts. Require explicit selection of the visible interpretation before a later comparison; pin that exact profile on the comparison.

Replacing the human brief with a generated successor would misattribute model output and could weaken exclusions or unknown handling. Automatically using the latest interpretation would change historical assessment meaning and hide a revision race. Instead, preserve the original profile and all attempts. Validate current brief before dispatch acknowledgment and again before exposing success; a successor during transport yields a visible stale result that cannot execute. Exact retry identities reopen existing attempts rather than dispatching another possible charge. Process loss preserves an uncertain in-progress attempt, with no invented response recovery.

The Responses port includes a disabled-by-default provider HTTPS adapter and an explicit simulated mode. Explicit model identity, finite bounds, rate classification, measurement basis and weighting policy are required. Reuse [the shared cost admission](0006-bounded-synthetic-admission.md) before one transport invocation; settle valid reported usage even for unusable interpretation outcomes. Missing usage or lost transport keeps its liability, with [final evidence and meter recovery](0007-final-cost-evidence-and-meter-recovery.md) owned by accounting. This accepts visible unavailable/uncertain states over invented free success. Provider dispatch pins a verified model input/context contract and standard-tier output bounds; real execution requires explicit server enablement. Default tests intercept external HTTP. Final invoices, account readiness, provider-side cancellation/billing-lag guarantees and human language/usefulness validation remain independently unverified.
