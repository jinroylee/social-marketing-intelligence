## Delivered

- Campaign-owned `supported-campaign-coverage-v1` atomically pins policy, server UTC clock, exact comparison/candidate input references, counts and quantity/relevance/freshness reasons on every new deterministic or successfully saved ranked recommendation. One explicit policy requires three eligible supported accounts, three with pinned satisfied include-criterion support and three with all known/nonfuture support captures within 30 days. These are local operating thresholds, not marketing/market-completeness claims. Import/publication time never refreshes a capture; unknown/future captures remain explicit. Legacy/human assessments stay null.
- `CampaignRecommendations` composes public campaign save with task admission afterward, preserving the campaign→knowledge and tasks→campaign dependency direction. The recommendation commits first and remains readable if admission fails. `require_current_brief` now returns its exact source-free human brief/document under the same caller-owned campaign lock; discovery never needs a source-heavy campaign-history read.
- `AcquisitionTasks.submit_campaign_discovery` uses an exact operator-configured campaign actor, saved coverage and current human brief. It derives one explicit first-product catalog-name/subject query (brand fallback), saved-clock 30-day window intersected with human publication bounds, exact catalog digest and configured offline route/limits. Empty windows, unsupported campaign platforms, unavailable supplied-reference capability, missing route and source processing/retention denial refuse truthfully. TikTok-only route coverage and unsearched platforms are explicit. No objective/generated/model/source text can assign authority, scope configuration or spending controls; assistant proposals still require exact human approval.
- One task-owned `campaign_discovery_requests` row per shortlist atomically commits a not-needed/refused disposition or its exact task. A fresh server-owned nested task identity prevents public request preclaims. Concurrent/restarted exact retries reopen the original disposition before changed clocks/briefs/configuration; an interrupted admission reuses saved assessment inputs and checks the current human brief. Task/disposition rollback leaves the saved result intact. No duplicate submission or historical reevaluation occurs.
- Current-policy reads withhold aggregate coverage inputs/results when assessed support is unavailable, superseded or purged. Exact source bodies remain owned/purged by comparison dependencies; metadata stores no duplicated source wording/dates. Historical policy/clock and permitted shortlist membership/producer remain pinned, without reconstructing purged input.
- Both protected HTTP recommendation actions use the new save-first composition and server campaign-role configuration. Shortlist pages show readable quantity/relevance/freshness counts against thresholds, assessment time, reasons and current task/refusal/wait status; exact policy/input IDs are optional details. Empty/current supported results remain usable while work is queued, running, waiting or terminal. Actual shared worker cost admission supplies waiting/refusal reasons and resume semantics; no new budget, price, free classification, worker fencing, receipt or accounting implementation was added. Discovery completion never changes a shortlist.
- Added glossary terminology, ADR 0010, product contracts, architecture, physical ERD/dictionary and existing/new module guidance. New `smi_tasks.campaigns` owner has `CLAUDE.md -> AGENTS.md`; existing relative instruction pairs remain intact. Campaign test fixtures now install the task schema prerequisite used by the full browser journey; production `migrate` already installed it.

## Limits and handoff

Literal relevance and capture recency do not establish complete market research, human ranking usefulness, audience geography, fees, contracts, availability, sales or full history. The first-product/brand literal query searches a declared TikTok subset and conservative time intersection; other products/aliases/platforms are not silently expanded. Source/configuration refusals remain immutable historical dispositions; worker monetary waiting can resume under its existing controls.
