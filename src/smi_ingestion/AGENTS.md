# Acquisition and canonical evidence

Own source observations, bounded acquisition checkpoints, source policy, canonical identity/mapping and their schema. Collectors implement `Collector`; deterministic mappers implement `Mapper`; `IngestionRunner` coordinates them through `EvidenceStore` and `CanonicalWriter`. Downstream owners read exact support through `smi_ingestion.support` and retain their own task/publication decisions.

Commit each observation and its collection frontier together, then commit canonical mapping. `resume(..., on_commit=...)` notifies only after durable evidence/canonical commits; observer exceptions propagate. `inspect` reads committed counts without collection or state advancement. Recover retained pending observations and reuse committed derivations; unavailable replay stays an explicit failure rather than an implicit refetch.

For task-owned runs, `resume(..., transaction=...)` joins the supplied owner connection for every mutation, including reconciliation, usage/checkpoints, issues/quarantine, canonical application and run completion. Check ownership before collector dispatch; keep collection/normalization outside transaction scopes and notify after commit. Caller-owned connection support in source/canonical operations preserves task fencing; opening a separate mutation connection after an ownership check permits stale effects. Clean uncommitted payload files only after confirming their observation did not commit.

For no-observation results, commit checkpoint, completion/waiting metadata and actual request use together through `EvidenceStore.advance`. A pending wait promises safe resume of that saved operation; an ambiguous wait stays blocked until route-specific reconciliation. Keep opaque operation handles in ingestion, exposing only sanitized wait reasons/resumability to tasks. Apply persisted bounds before every collector call.

Keep admission authority, publication availability, notifications and monetary decisions with their owners. Verify public ingestion/task operations with real PostgreSQL and simulated external I/O; align schema, physical ERD and source/task contracts when progress semantics change.

For scheduled canonical admission, `resume(..., admission=...)` passes the public `CanonicalAdmission` callback into `CanonicalWriter.apply`. After policy/mapping validation, lock all normalized identities in deterministic order and supply known identities before creating any canonical entities/derivations. Commit the callback’s decisions, canonical effects and applied/skipped source status on the same supplied connection. Ingestion owns no schedule SQL or allowance policy. Failed application rolls back consumption; skipped observations stay explicit and cannot enter run support.

`resume(..., policy_version=...)` passes an explicit trusted canonical processing revision into `CanonicalWriter.apply` for both retained pending observations and newly collected pages. Default `canonical-v1` preserves existing mappings. This is distinct from the registered mapper software version; task callers pin the revision in immutable scope. Preserve the supplied admission callback and fenced connection for either path.

No-observation batches can report `response_bytes`; `advance` commits their actual byte consumption with the saved checkpoint/request count under the run's existing cumulative budget. Default zero preserves older collectors. Source wait handles remain opaque; live keyword retry clocks and terminal status interpretation belong to its adapter.
